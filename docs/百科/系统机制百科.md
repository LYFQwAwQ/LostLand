## 2. 英雄生成机制

### 2.1 生成流程

1. 启动时先加载固定英雄（`BASE_FIXED_HEROES`）。
2. 按 `randomHeroCountPerStartup` 逐个生成随机英雄槽位。
3. 每个槽位先判定是否出传奇英雄（若传奇池仍有未占用角色）。
4. 未出传奇时，走普通英雄生成（职业、名字、属性、成长、技能包）。

### 2.2 核心公式

- 职业抽取概率：
  - `P(class_i) = classRollWeights[i] / Σ classRollWeights`
- 传奇判定（每个随机槽位一次）：
  - `random() < legendarySpawnChance`
- 普通英雄基础属性（每个属性独立）：
  - `stat = round(base + (2r - 1) * variance)`，其中 `r ∈ [0,1)`
- 普通英雄成长属性（每个属性独立）：
  - `growth = round(base + (2r - 1) * variance)`
- 技能数量组合权重（控制“技能越多越稀有”）：
  - `weight = decay^(totalCount - minTotalCount)`
- 随机技能稀有度抽取：
  - 先将 `randomSkillRarityWeights` 归一化，再按权重抽取 `common/rare/epic`。

### 2.3 配置入口

- `src/data/config/heroGeneration.json`
  - 随机英雄数量、传奇概率、职业权重、名称池、职业标题/头像池、属性与成长基线、技能池规则。
- `src/data/config/legendaryHeroes.json`
  - 传奇英雄固定模板（属性、成长、技能）。

## 3. 英雄等级与经验机制

### 3.1 等级边界

- 初始等级：`1`
- 等级上限：`100`

### 3.2 升级经验公式

- 下一等级所需经验（`Lv -> Lv+1`）：
  - `needExp(Lv) = base + linear * (Lv - 1) + quadratic * (Lv - 1)^2`
- 当前配置（`heroProgressionConfig.ts`）：
  - `base=120, linear=35, quadratic=8`

### 3.3 战斗经验公式

- 战斗基础经验（按敌人列表求和）：
  - `baseExp = Σ(enemyBase + enemyLevelFactor * enemyLevel_i)`
- 敌我等级差倍率（`delta = enemyAvgLevel - heroLevel`）：
  - `delta >= 0` 时：`mult = 1 + delta * bonusPerLevel`
  - `delta < 0` 时：`mult = 1 / (1 + |delta| * penaltyPerLevel)`
  - 最终：`mult = clamp(mult, minMultiplier, maxMultiplier)`
- 单英雄实际获得经验：
  - `gainExp = floor(baseExp * mult)`
  - 当前实现是“每个参战英雄独立按该公式吃满经验”，不做队内均分。

### 3.4 配置入口

- `src/data/config/heroProgressionConfig.ts`

## 4. 装备生成机制

### 4.1 生成维度

- 装备模板：`equipmentTemplates.ts`
- 品阶（Rank）：`crude/fine/superior/perfect`
- 品质（Quality）：`common/uncommon/rare/epic/legendary/mythic`
- 词条数量由品质决定（0~5条）

### 4.2 核心公式

- 品阶抽取：按模板 `rankWeights`（可叠加环境倍率）
- 品质抽取：按模板 `qualityWeights`（可叠加环境倍率）
- 品阶百分比：
  - 在该品阶对应区间内均匀抽样（如 `fine` 为 `0.05~0.15`）
- 主词条基础值：
  - `baseValue = lvl1Base + (level - 1) * growthRate`
  - `finalValue = baseValue * (1 + rankPercent)`
- 附加词条值：
  - `rolledValue = random(min, max)`
  - `finalValue = rolledValue * (1 + rankPercent)`
- 插槽数：
  - `socketCount = floor(level / SOCKET_UNLOCK_LEVEL_STEP)`（当前步长 `20`）

### 4.3 配置入口

- `src/data/equipmentTemplates.ts`
- `src/lib/equipmentSystem.ts`（生成规则与常量）

## 5. 装备强化机制

> 强化材料链的详细表格见：`docs/百科/装备强化消耗图鉴.md`

### 5.1 强化规则

- 普通装备上限：`+10`
- 传说装备上限：`+15`
- 失败不掉级
- 默认失败消耗资源（金币 + 主材料）
- 可选辅助材料：
  - 幸运护符：增加当次成功率
  - 固守符印：失败时保护主材料（金币仍扣）

### 5.2 核心公式

- 强化金币：
  - `goldCost = round(itemLevel * levelFactor * enhancementGrowth^targetLevel)`
- 材料消耗：
  - `materialCount = ceil((baseQuantity + growthPerLevel * (targetLevel - 1)) * stageMultiplier)`
- 成功率上限：
  - `capByMultiplier = baseSuccessRate * capByBaseMultiplier`
  - `successRateCap = max(baseSuccessRate, min(absoluteCap, capByMultiplier))`
- 最终成功率：
  - `finalSuccessRate = min(successRateCap, baseSuccessRate + forgeBonusRate + aidBonusRate)`

### 5.3 强化属性生效口径（战斗适配）

- 强化加成只作用于装备 `t1Stats`：
  - `t1Final = t1Stat.finalValue * (1 + enhanceBonus)`
- 附加词条 `affixes` 当前不吃强化倍率（按原值生效）。

### 5.4 配置入口

- `src/data/config/equipmentEnhancementConfig.ts`
- `src/data/config/equipmentEnhancementAidConfig.ts`
- 结算实现：`src/state/EquipmentInventoryProvider.tsx`

## 6. 装备打造机制

### 6.1 机制说明

- 打造为“固定配方消耗 -> 生成指定模板装备”的确定性入口。
- 可控字段：模板 ID、目标品质、目标等级、材料列表、金币成本。
- 配方读取时会做合法性校验：
  - 模板 ID 必须存在于 `equipmentTemplates`
  - 材料 ID 必须存在于“战斗材料 + 建筑材料”目录
  - 消耗数量和金币必须大于 0

### 6.2 结算流程

1. 校验背包容量（普通装备容量上限）。
2. 校验金币与材料库存。
3. 扣除金币与材料（复用统一扣费接口）。
4. 按配方模板生成装备并锁定目标品质。
5. 装备写入背包掉落池（入包）。

### 6.3 相关公式

- 节点入口配方金币展示浮动：
  - `displayGoldCost = round(baseRecipeGoldCost * (1 + index * 0.08))`
  - `index` 为节点内配方排序位次（轮换后顺序）。

### 6.4 配置入口

- 主配置：`src/data/config/forgeCraftingRecipes.json`
- 配置读取：`src/data/config/forgeCraftingConfig.ts`
- 页面入口：`src/components/forge/ForgeCraftPanel.tsx`

## 7. 经济交易机制（装备）

### 7.1 价格链路

- `basePrice`（基础交易价）
- `buyPrice`（买入价）= `basePrice * buyMarkup`
- `sellPrice`（卖出价）= `basePrice * sellRatio`
- 最后都会按 `roundStep` 四舍五入并受最小价保护。

### 7.2 基础价公式

- `normalizedScore = max(0, score) / scoreNormalizationBase`
- `scoreMultiplier = 1 + normalizedScore * scoreBlendWeight`
- `enhanceMultiplier = 1 + floor(enhanceLevel) * enhancementLevelPriceWeight`
- `levelBase = floor(level) * levelPriceFactor`
- `raw = levelBase * qualityMultiplier * rankMultiplier * scoreMultiplier * enhanceMultiplier`
- `basePrice = max(minBasePrice, roundToStep(raw, roundStep))`

### 7.3 规则

- 传说装备不可卖出（硬规则）。
- 已穿戴、已锁定装备不可卖出。

### 7.4 配置入口

- `src/data/config/economyConfig.ts`

## 8. 布告栏任务机制

### 8.1 生成逻辑

- 按疆域配置生成“收集任务 + 讨伐任务”。
- 任务目标从该疆域（及同疆域地区）可达敌人和可掉落材料中抽样。
- 任务状态机：
  - `available -> in_progress -> ready_to_submit(hunt) -> completed`

### 8.2 核心公式

- 收集目标数量：
  - 在 `collect.targetTypeCountRange` 内随机
- 讨伐目标数量：
  - 在 `hunt.targetTypeCountRange` 内随机
- 奖励评分：
  - `baseScore = collectScore + huntScore`
  - `collectScore = Σ(requiredQuantity * rarityWeight)`
  - `huntScore = Σ(requiredCount * 1.35)`
- 奖励赏金：
  - `bounty = max(min, round((base + baseScore * perScore) * swing))`
- 奖励声望：
  - `reputation = max(min, round((base + baseScore * perScore) * swing))`
- 可接任务上限：
  - `acceptedLimit = baseAcceptedLimit + extraCapacity`
  - `extraCapacity` 当前来自任务大厅等级加成。

### 8.3 配置入口

- `src/data/config/bulletinMissions/*.json`
- `src/data/config/bulletinMissionConfig.ts`
- 生成实现：`src/lib/bulletinMissionSystem.ts`

## 9. 战斗掉落机制

### 9.1 掉落流程

- 以“每个敌方单位”为粒度独立结算材料与装备掉落。
- 材料掉落次数、装备掉落次数由敌人稀有度决定。

### 9.2 核心公式

- 材料掉落次数：
  - `materialRolls = randomInt(config.materialRolls[min,max])`
- 装备掉落次数：
  - `equipmentRolls = randomInt(config.equipmentRolls[min,max])`
- 材料抽样权重：
  - `finalMaterialWeight = baseWeight * rarityWeightByEnemyRarity[materialRarity]`
- 材料数量：
  - `quantity = randomInt(material.quantity[min,max])`
- 掉落装备等级：
  - `dropLevel = clamp(enemyLevel + levelOffset, 1, 30)`

### 9.3 配置入口

- `src/data/battleDrops.ts`

## 10. 战斗计算机制（核心公式）

### 10.1 行动条推进

- 每步推进：
  - `actionValue += agi * ACTION_SPEED_COEFFICIENT * deltaSeconds * speedMultiplier`
- 当前常量：
  - `ACTION_SPEED_COEFFICIENT = 42`
  - `ACTION_THRESHOLD = 10000`

### 10.2 技能基础威力

- `skillBase = basePower + str*ks + int*ki + agi*ka + def*kd + maxHp*kh + missingHp*km`

### 10.3 命中、暴击、防御、元素与最终伤害

- 闪避判定：
  - `random < clamp(target.evasion, 0, EVA_CAP)` 则 miss（`EVA_CAP=0.5`）
- 暴击判定：
  - `random < clamp(attacker.critRate, 0, 0.95)`，暴击倍率 `critDamage`
- 有效防御：
  - `effectiveDef = max(0, target.def * (1 - armorPenPct) - penetration)`
- 防御区间：
  - `defZone = DEFENSE_K / (DEFENSE_K + effectiveDef)`（`DEFENSE_K=1000`）
- 元素区间：
  - `elemZone = (1 + elementBoost + allBoost) * (1 - effectiveRes)`
- 最终伤害：
  - `finalDamage = round(basePower * critZone * defZone * elemZone * undeadZone * extraZone * reductionZone)`
  - 再经护盾吸收后写入 HP。

### 10.4 吸血与反伤

- 吸血回复：
  - `heal = round(dealt * lifeSteal)`
- 反伤：
  - `reflect = round(dealt * thorns)`

### 10.5 代码入口

- `src/lib/battleEngine.ts`

## 11. 组织建筑衍生机制

### 11.1 评级上限（基地核心）

- `rankCap = min(maxRank, baseRankCap + (baseCoreLevel - 1) + extraBonus)`

### 11.2 任务上限加成（任务大厅）

- `missionAcceptedLimitBonus = floor(missionHallLevel / 2)`

### 11.3 强化成功率加成（铁匠铺）

- `forgeEnhancementBonusRate = (foundryLevel - 1) * 0.01`

### 11.4 训练营加成

- 经验加成：
  - `trainingExpBonusRate = (trainingCampLevel - 1) * 0.02`
- 槽位数：
  - Lv1~2: 1 槽  
  - Lv3~6: 2 槽  
  - Lv7~9: 3 槽  
  - Lv10+: 5 槽

### 11.5 配置入口

- `src/data/organizationData.ts`
