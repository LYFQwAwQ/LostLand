# 05. 状态管理与数据模块

## 1. 先看这个模块的原因

后续开发者最容易出问题的地方，不是“不会写功能”，而是不知道数据到底归谁管。本文件只解决这个问题。

## 2. 状态归属总表

| 状态 | 唯一来源 | 主要消费者 |
| --- | --- | --- |
| 地区缓存、世界月份、世界日志 | `MapSystemProvider` | `MainLayout` `WorldMapPage` `NodeHubPage` `NodeActionPage` `BattlePage` |
| 布告栏任务、任务警告、已接取任务计数 | `MapSystemProvider` | `NodeActionPage` `BattlePage` `OrganizationPage` |
| 编队、技能槽位 | `BattleSetupProvider` | `TeamPage` `HeroPage` `BattlePage` |
| 装备库存、材料、消耗品、记忆、穿戴关系 | `EquipmentInventoryProvider` | `InventoryPage` `HeroPage` `NodeActionPage` `BattlePage` `TeamPage` |
| 组织领地、建筑摆放、等级进度 | `OrganizationProvider` | `OrganizationPage` |
| 初始英雄列表 | `src/data/mockData.ts` 中的 `heroes` 常量 | `HeroPage` `TeamPage` `BattleSetupProvider` `EquipmentInventoryProvider` `BattlePage` |

## 3. Provider 说明

### 3.1 `MapSystemProvider`

文件：`src/state/MapSystemProvider.tsx`

负责：

1. `regionsById`
   - 懒加载后的地区缓存
2. `worldMonth`
3. `worldLogs`
4. `missionsByRegionId`
5. `missionWarningByRegionId`

核心方法：

- `ensureRegionLoaded(regionId)`
- `advanceOneMonth(regionId)`
- `findNodeById(nodeId)`
- `getRegionBulletinMissions(regionId)`
- `getAcceptedBulletinMissions()`
- `acceptBulletinMission(regionId, missionId)`
- `submitBulletinMission(regionId, missionId)`
- `reportMissionBattleOutcome(outcome)`

关键任务状态补充：

- `acceptedMissionLimit`
- `acceptedMissionCount`

其中 `acceptedMissionLimit` 来自 `src/data/config/bulletinMissionConfig.ts` 的 `getBulletinMissionAcceptedLimit()`，当前默认 4。

适合放进这里的状态：只要它跟地区、任务、世界月份强绑定，就放这里。

### 3.2 `BattleSetupProvider`

文件：`src/state/BattleSetupProvider.tsx`

负责：

1. `formation`
2. `heroLoadouts`
3. 编队重置、导入导出
4. 技能槽位修改

特点：

- 初始化依赖 `heroes`
- 会对技能槽位做规范化和职业校验
- 不负责装备和记忆

### 3.3 `EquipmentInventoryProvider`

文件：`src/state/EquipmentInventoryProvider.tsx`

负责：

1. 随机装备批次 `items`
2. 装备穿戴关系 `equippedByHero`
3. 材料库存 `materialStock`
4. 消耗品库存 `consumableStock`
5. 已拥有记忆 `ownedMemoryIds`
6. 已装备记忆 `equippedMemoryByHero`

核心方法：

- `refreshItems()`
- `collectBattleDrops()`
- `grantMissionRewards()`
- `consumeMaterials()`
- `equipItem()` / `unequipItem()`
- `setHeroMemory()`
- `exportSnapshot()` / `importSnapshot()`

适合放进这里的状态：任何和背包、库存、穿戴、记忆有关的都放这里。

### 3.4 `OrganizationProvider`

文件：`src/state/OrganizationProvider.tsx`

负责：

1. 建筑摆放 `placements`
2. 已解锁领地 `revealedCells`
3. 组织评级 `rankState`
4. 可扩张次数 `pendingExpansionCount`

适合放进这里的状态：组织基地地图、建筑、领地进度。

## 6. 当前最容易误判的地方

### 6.1 `heroes` 不是 Provider

很多功能看起来像“应该有一个 HeroProvider”，但当前没有。

如果你要做：

- 酒馆招募入队
- 英雄永久持久化
- 运行时新增英雄
- 真正的队伍/仓库分离

请先设计新的英雄状态层，再动页面。

### 6.2 任务奖励没有完整经济状态落地

当前：

- 材料和消耗品奖励会入背包
- 赏金/声望只在任务奖励文案中展示

如果要做正式经济系统，不应该塞进页面里，需要设计新的状态源。

### 6.3 一些页面显示用数据不是业务真相

例如 HeroPage 的一部分展示属性仍是演示型文案，真正战斗数值由 `battleAdapters.ts` + `battleEngine.ts` 组装和计算。

## 7. 什么时候该新建 Provider，什么时候不该

### 适合新建 Provider

1. 该状态被多个页面共享
2. 该状态有明确唯一真相
3. 页面卸载后仍应保留
4. 未来可能需要导入导出 / 持久化 / 回滚

### 不适合新建 Provider

1. 只是弹窗开关
2. 只是 hover / 选中态
3. 只在单页局部使用
4. 只是渲染辅助变量

## 8. 常见改动定位

| 需求 | 文件 |
| --- | --- |
| 新增地图状态或任务状态 | `src/state/MapSystemProvider.tsx` |
| 新增装备/库存状态 | `src/state/EquipmentInventoryProvider.tsx` |
| 新增编队/技能槽状态 | `src/state/BattleSetupProvider.tsx` |
| 新增组织状态 | `src/state/OrganizationProvider.tsx` |
| 新增共享数据结构 | `src/types/*.ts` |
| 新增静态配置文件 | `src/data/config/*` 或 `src/config/*` |

## 9. 建议的修改顺序

1. 确认状态归属
2. 改类型
3. 改 data / config
4. 改 Provider / lib
5. 最后改页面
