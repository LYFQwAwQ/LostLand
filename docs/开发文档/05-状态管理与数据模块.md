# 05. 状态管理与数据模块

## 1. 模块职责

- 承载全局地图状态（懒加载地区缓存、月份、日志）。
- 承载全局装备状态（背包样本、穿戴映射、装备归属）。
- 承载全局战斗配置状态（队伍站位、英雄技能槽位、记忆占位）。
- 承载组织基地状态（建筑配置、占地校验、组织评级、战争迷雾与地块扩张）。
- 提供节点查找和区域查询 API 给页面层。
- 组织初始数据和强类型定义。

## 2. 关键文件

- `src/state/MapSystemProvider.tsx`
  - 地图全局状态容器（地区懒加载 + 地区缓存）
  - `ensureRegionLoaded(regionId)` 地区按需初始化入口
  - `advanceOneMonth(regionId)` 当前地区月结算入口
  - `getRegionById()`、`findNodeById()` 查询方法
- `src/data/worldMapData.ts`
  - 世界层级配置读取与校验
  - URL 三参数（`continent/dominion/region`）解析
  - 地区元数据查询（含邻接地区）
- `src/config/world/worldHierarchy.json`
  - 大陆/疆域/地区静态配置（含规模、复杂度、势力权重等）
- `src/state/EquipmentInventoryProvider.tsx`
  - 全局装备状态容器
  - `refreshItems()` 背包样本刷新入口
  - `equipItem()`/`unequipItem()` 穿戴写入入口
  - `getItemOwner()` 装备归属查询（用于跨页面标记与去重）
  - `exportSnapshot()/importSnapshot()` 装备快照导入导出（预设保存）
- `src/state/BattleSetupProvider.tsx`
  - 全局战斗配置容器
  - `formation` 前后排编队状态
  - `heroLoadouts` 英雄天赋/主动/被动槽位状态
  - `heroMemories` 英雄记忆占位状态
  - `exportSnapshot()/importSnapshot()` 编队构筑快照导入导出
- `src/state/OrganizationProvider.tsx`
  - 组织系统全局状态容器
  - `checkPlacement()` 建筑占地与边界校验
  - `checkTerritoryExpansion()` 扩展范围预检（边界/相邻/不相交）
  - `expandTerritory()` 战争迷雾地块扩张（按补丁尺寸解锁可建造格）
  - `placeBuilding()/removeBuilding()/upgradeBuilding()` 建筑实例操作
  - `addMockOrganizationExp()` 组织评级经验占位接口
- `src/data/mockData.ts`
  - 初始日志、英雄数据
- `src/data/organizationData.ts`
  - 组织建筑定义、网格尺寸、缩放参数、评级经验参数
- `src/types/game.ts`
  - 系统核心类型（含 `DominionStaticConfig`）
- `src/types/organization.ts`
  - 组织建筑、占地格、评级、校验结果类型

## 3. 状态模型（核心字段）

- `regions: RegionTopology[]`
  - 已加载地区集合（懒生成，不再开局一次性创建全部地区）
- `worldMonth: number`
  - 世界总月份（左侧日志和地图信息显示）
- `worldLogs: string[]`
  - 左侧冒险日志展示内容
- `items: GeneratedEquipment[]`
  - 全局背包样本（英雄页与背包页共享）
- `equippedByHero: Record<heroId, Record<slotId, itemUid>>`
  - 英雄穿戴映射（按英雄 + 槽位记录）
- `formation: TeamFormationSlotState[]`
  - 队伍上阵位映射（前排/后排各 3 位）
- `heroLoadouts: Record<heroId, BattleLoadout>`
  - 英雄战斗技能槽位（1 天赋 + 10 主动 + 10 被动）
- `heroMemories: Record<heroId, memoryId>`
  - 英雄记忆占位选择（当前用于预设保存与后续策划文本接入）
- `placements: OrganizationBuildingPlacement[]`
  - 已建造建筑实例列表（定义 ID、原点坐标、等级）
- `occupancy: Record<string, string>`
  - 地块占用映射（`x,y -> instanceId`）
- `revealedCells: Record<string, true>`
  - 已开发地块集合（未开发区域默认处于战争迷雾）
- `rankState: OrganizationRankState`
  - 组织评级状态（等级、当前经验、下一等级需求）
- `pendingExpansionCount: number`
  - 组织升级后待选择的地块扩张次数（每次消耗 1 次）

## 4. 常见修改任务

## 4.1 调整世界层级结构

修改 `src/config/world/worldHierarchy.json`：

- 新增/删除大陆：`continents`
- 新增/删除疆域：`dominions`
- 新增/删除地区与邻接：`regions`

## 4.2 调整默认地图定位

修改 `src/data/worldMapData.ts` 的默认选择推导逻辑（`DEFAULT_WORLD_SELECTION`）。

## 4.3 扩展系统类型

修改 `src/types/game.ts`，并同步所有使用点：

- 页面类型守卫
- `mapRules` 映射表
- `monthlySimulation` 逻辑

## 4.4 装备状态常见改动

修改 `src/state/EquipmentInventoryProvider.tsx`：

- 调整背包样本规模：`buildInventory()` 内 `generateEquipmentBatch(..., count)`。
- 调整刷新逻辑：`refreshItems()` 中的 `seed` 生成方式。
- 调整唯一穿戴规则：`equipItem()` 内归属判定逻辑（默认全局唯一）。
- 双手武器规则：`equipItem()` 支持双手武器占用两个手部槽位，并通过 `forceReplaceHand` 控制是否允许替换另一手装备。
- 预设装备快照：`exportSnapshot()/importSnapshot()` 用于保存/恢复 `seed + equippedByHero`。
- 若新增装备持久化（本地存档/后端），优先在该 Provider 层封装，避免页面直接维护副本。

## 4.5 战斗配置状态常见改动

修改 `src/state/BattleSetupProvider.tsx`：

- 调整默认编队：`DEFAULT_FORMATION`
- 调整默认技能槽位：`buildDefaultHeroLoadouts()`
- 调整默认记忆占位：`buildDefaultHeroMemories()`
- 技能槽位写入规则：`setHeroTalent / setHeroActiveSkill / setHeroPassiveSkill`
- 队伍站位替换规则：`setSlotHero()`（已上阵英雄会与目标槽位交换）
- 预设快照入口：`exportSnapshot()/importSnapshot()`（供队伍页预设系统调用）

## 4.6 组织系统状态常见改动

修改 `src/state/OrganizationProvider.tsx`：

- 新增建筑类型与占地形状：`src/data/organizationData.ts -> organizationBuildingDefinitions`
- 调整占地冲突规则：`checkPlacement()`
- 调整战争迷雾与可建造区域：`revealedCells`、`expandTerritory()`
- 调整扩展预检逻辑：`checkTerritoryExpansion()`（供扩展模式悬停预览与点击扩展共用）
- 初始领地规则：`initialTerritorySize`（默认初始 `40x40`）
- 调整扩张校验：扩张块需在领地外、与现有领地相邻、且不能相交
- 调整唯一建筑规则：`definition.unique` 与放置校验
- 调整评级成长接口：`addMockOrganizationExp()`（升级时增加 `pendingExpansionCount`，当前仍为模拟经验）
- 若后续接后端/存档，优先在 Provider 层统一封装，不要在页面维护并行副本

## 5. 注意事项

- 页面层优先用 `useMapSystem()` 读取数据，不要在页面里维护并行状态副本。
- 地图页 URL 已升级为三参数：`continent`、`dominion`、`region`；新增跳转请保持一致。
- `MapSystemProvider` 当前是“只结算当前地区”；如需全图/全世界结算，请扩展 `advanceOneMonth` 策略。
- 页面层优先用 `useEquipmentInventory()` 读取装备数据，不要在 `HeroPage`/`InventoryPage` 各自维护独立背包。
- 页面层优先用 `useBattleSetup()` 读取编队/技能配置，不要在 `TeamPage`/`HeroPage` 维护独立战斗副本状态。
- 队伍预设会跨 Provider 读写状态（`BattleSetup + EquipmentInventory`），新增构筑字段时需同步快照结构，避免预设漏字段。
- 页面层优先用 `useOrganization()` 读取组织状态，不要在组织页里维护并行占地副本。
