# 05. 状态管理与数据模块

## 1. 先看这个模块的原因

后续开发者最容易出问题的地方，不是“不会写功能”，而是不知道数据到底归谁管。本文件只解决这个问题。

## 3. Provider 说明

### 3.1 `MapSystemProvider`

文件：`src/state/MapSystemProvider.tsx`

负责：

1. `regionsById`
   - 懒加载后的地区缓存
2. `worldMonth`
3. `worldLogs`
4. `missionsByRegionId`
5. `missionWarningByRegionId`
6. `suppressionProgressByRegionId`（玩家治理带来的地区压制增量）

核心方法：

- `ensureRegionLoaded(regionId)`
- `advanceOneMonth(regionId)`
- `findNodeById(nodeId)`
- `getRegionBulletinMissions(regionId)`
- `getAcceptedBulletinMissions()`
- `acceptBulletinMission(regionId, missionId)`
- `submitBulletinMission(regionId, missionId)`
- `reportMissionBattleOutcome(outcome)`

压制值补充规则：

- 压制值语义：`0-100`，越高表示越稳定、越接近完全解放。
- 玩家治理增量来源：
  - 讨伐胜利：按节点类型提升压制（`BL1 +8` / `BL2 +5` / `BL3 +3`）。
  - 任务提交：每次提交地区任务提升压制（`+4`）。
- 月结算后会叠加玩家治理增量，避免“玩家行为带来的解放进度”被纯月度演化覆盖。
- 当地区压制达到 `100` 时触发“完全解放态”：
  - 该地区当前所有活跃 `BL1` 会被清除（转换为 `BL2`），不再保留最高级不稳定节点。

关键任务状态补充：

- `acceptedMissionLimit`
- `acceptedMissionCount`

其中 `acceptedMissionLimit` 基础值来自 `src/data/config/bulletinMissionConfig.ts` 的 `getBulletinMissionAcceptedLimit()`，并叠加 `OrganizationProvider` 回写的额外容量（当前由任务大厅等级驱动）。

适合放进这里的状态：只要它跟地区、任务、世界月份强绑定，就放这里。

### 3.2 `BattleSetupProvider`

文件：`src/state/BattleSetupProvider.tsx`

负责：

1. `formation`
2. `heroLoadouts`
3. 编队重置、导入导出
4. 技能槽位修改

特点：

- 初始化依赖 `heroes`
- 会对技能槽位做规范化和职业校验
- 不负责装备和记忆

### 3.3 `EquipmentInventoryProvider`

文件：`src/state/EquipmentInventoryProvider.tsx`

负责：

1. 随机装备批次 `items`
2. 战斗掉落装备池（真实入包）
3. 装备穿戴关系 `equippedByHero`
4. 材料库存 `materialStock`
5. 消耗品库存 `consumableStock`
6. 已拥有记忆 `ownedMemoryIds`
7. 已装备记忆 `equippedMemoryByHero`
8. 经济状态 `gold` / `reputation`
9. 已卖出装备 UID 集合（用于从测试基础库存中移除）
10. 英雄成长状态 `heroProgressById`（等级/经验）
11. 强化辅助材料库存 `enhancementAidStock`（幸运护符 / 固守符印）

核心方法：

- `refreshItems()`
- `collectBattleDrops()`
- `grantBattleHeroExp()`
- `grantMissionRewards()`
- `buyEquipment()` / `craftEquipment()` / `sellEquipment()`
- `getEquipmentEnhancementPreview()` / `enhanceEquipment()`
- `consumeMaterials()`
- `equipItem()` / `unequipItem()`
- `setHeroMemory()`
- `exportSnapshot()` / `importSnapshot()`

适合放进这里的状态：任何和背包、库存、穿戴、记忆有关的都放这里。

补充：

- `collectBattleDrops()` 现在会同时写入“材料 + 装备”。
- `grantBattleHeroExp()` 会按“敌人等级 + 数量 + 敌我等级差修正”给参战英雄发放经验并处理升级。
- `refreshItems()` 仍是测试期“重刷随机样本”入口，会清掉战斗掉落装备池（避免测试残留影响）。
- `grantMissionRewards()` 会同时结算材料 / 消耗品 / 赏金 / 声望。
- 装备出售存在硬规则：传说装备禁止出售；已穿戴装备禁止出售。
- 装备强化支持“辅助材料”：
  - 幸运护符：提升当次成功率
  - 固守符印：失败时保护主材料不被消耗（金币仍会扣除）
- 装备打造已接入正式结算：
  - 校验背包容量、金币与材料
  - 扣除配方消耗并生成装备入包
  - 配方读取 `src/data/config/forgeCraftingRecipes.json`

### 3.4 `OrganizationProvider`

文件：`src/state/OrganizationProvider.tsx`

负责：

1. 建筑摆放 `placements`
2. 已解锁领地 `revealedCells`
3. 组织评级 `rankState`
4. 可扩张次数 `pendingExpansionCount`
5. 建筑等级衍生效果（基地核心评级上限、任务大厅任务上限加成、铁匠铺强化成功率加成）

适合放进这里的状态：组织基地地图、建筑、领地进度。

补充（第一章主线与门禁）：

- 第一章目标地区：`chapterTargetRegionId`
- 主线累计计数：`chapterMainlineCounters`
- 章节结算：`chapterCompletionSummary`
- 主线事件回写：
  - `reportChapterBuildMaterialPurchased`
  - `reportChapterBattleWin`
  - `submitChapterCoreUpgrade`
  - `reportChapterBuildingConstructed`
  - `syncChapterTargetSuppression`
- 功能门禁：
  - `canUseChapterFeature(feature)`
  - `getChapterFeatureLockMessage(feature)`
  - 当前受控功能包含：地图切换、节点铁匠铺、组织高级功能、组织建造权限（核心升级前锁建造）。

## 6. 当前最容易误判的地方

### 6.1 `heroes` 不是 Provider

很多功能看起来像“应该有一个 HeroProvider”，但当前没有。

如果你要做：

- 酒馆招募入队
- 英雄永久持久化
- 运行时新增英雄
- 真正的队伍/仓库分离

请先设计新的英雄状态层，再动页面。

### 6.2 任务奖励经济状态已落地（后续扩展点）

已完成：

- 材料和消耗品奖励会入背包
- 赏金和声望会写入 `EquipmentInventoryProvider` 的正式经济状态

后续若扩展“材料交易 / 消耗品交易 / 大宗贸易”，继续沿用该 Provider 经济链路，不要回退到页面临时状态。

### 6.3 一些页面显示用数据不是业务真相

例如 HeroPage 默认仍展示“原始数值”，但已支持切换到战斗结算数值；战斗值来源仍是 `battleAdapters.ts` + `battleEngine.ts`。

## 7. 什么时候该新建 Provider，什么时候不该

### 适合新建 Provider

1. 该状态被多个页面共享
2. 该状态有明确唯一真相
3. 页面卸载后仍应保留
4. 未来可能需要导入导出 / 持久化 / 回滚

### 不适合新建 Provider

1. 只是弹窗开关
2. 只是 hover / 选中态
3. 只在单页局部使用
4. 只是渲染辅助变量

## 8. 常见改动定位

| 需求 | 文件 |
| --- | --- |
| 新增地图状态或任务状态 | `src/state/MapSystemProvider.tsx` |
| 新增装备/库存状态 | `src/state/EquipmentInventoryProvider.tsx` |
| 新增编队/技能槽状态 | `src/state/BattleSetupProvider.tsx` |
| 新增组织状态 | `src/state/OrganizationProvider.tsx` |
| 新增共享数据结构 | `src/types/*.ts` |
| 新增静态配置文件 | `src/data/config/*` 或 `src/config/*` |

## 9. 建议的修改顺序

1. 确认状态归属
2. 改类型
3. 改 data / config
4. 改 Provider / lib
5. 最后改页面
