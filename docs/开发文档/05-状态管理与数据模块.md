# 05. 状态管理与数据模块

## 1. 模块职责

- 承载全局地图状态（区域、月份、日志）。
- 承载全局装备状态（背包样本、穿戴映射、装备归属）。
- 承载全局战斗配置状态（队伍站位、英雄技能槽位）。
- 提供节点查找和区域查询 API 给页面层。
- 组织初始数据和强类型定义。

## 2. 关键文件

- `src/state/MapSystemProvider.tsx`
  - 全局状态容器
  - `advanceOneMonth()` 月结算触发入口
  - `getRegionById()`、`findNodeById()` 查询方法
- `src/state/EquipmentInventoryProvider.tsx`
  - 全局装备状态容器
  - `refreshItems()` 背包样本刷新入口
  - `equipItem()`/`unequipItem()` 穿戴写入入口
  - `getItemOwner()` 装备归属查询（用于跨页面标记与去重）
- `src/state/BattleSetupProvider.tsx`
  - 全局战斗配置容器
  - `formation` 前后排编队状态
  - `heroLoadouts` 英雄天赋/主动/被动槽位状态
- `src/data/mockData.ts`
  - 大陆配置、初始日志、英雄数据、区域初始化入口
- `src/types/game.ts`
  - 系统核心类型

## 3. 状态模型（核心字段）

- `regions: RegionTopology[]`
  - 每个大陆一个 region，含 nodes/edges/currentMonth/report
- `worldMonth: number`
  - 世界总月份（左侧日志和地图信息显示）
- `worldLogs: string[]`
  - 左侧冒险日志展示内容
- `items: GeneratedEquipment[]`
  - 全局背包样本（英雄页与背包页共享）
- `equippedByHero: Record<heroId, Record<slotId, itemUid>>`
  - 英雄穿戴映射（按英雄 + 槽位记录）
- `formation: TeamFormationSlotState[]`
  - 队伍上阵位映射（前排/后排各 3 位）
- `heroLoadouts: Record<heroId, BattleLoadout>`
  - 英雄战斗技能槽位（1 天赋 + 10 主动 + 10 被动）

## 4. 常见修改任务

## 4.1 新增大陆（Region）

修改 `src/data/mockData.ts` 的 `continents`：

- 新增 `id/name/dominion/region/seed`
- `createInitialRegions()` 会自动遍历创建

## 4.2 调整默认地区

修改 `src/data/mockData.ts` 中 `defaultRegionId`。

## 4.3 扩展系统类型

修改 `src/types/game.ts`，并同步所有使用点：

- 页面类型守卫
- `mapRules` 映射表
- `monthlySimulation` 逻辑

## 4.4 装备状态常见改动

修改 `src/state/EquipmentInventoryProvider.tsx`：

- 调整背包样本规模：`buildInventory()` 内 `generateEquipmentBatch(..., count)`。
- 调整刷新逻辑：`refreshItems()` 中的 `seed` 生成方式。
- 调整唯一穿戴规则：`equipItem()` 内归属判定逻辑（默认全局唯一）。
- 双手武器规则：`equipItem()` 支持双手武器占用两个手部槽位，并通过 `forceReplaceHand` 控制是否允许替换另一手装备。
- 若新增装备持久化（本地存档/后端），优先在该 Provider 层封装，避免页面直接维护副本。

## 4.5 战斗配置状态常见改动

修改 `src/state/BattleSetupProvider.tsx`：

- 调整默认编队：`DEFAULT_FORMATION`
- 调整默认技能槽位：`buildDefaultHeroLoadouts()`
- 技能槽位写入规则：`setHeroTalent / setHeroActiveSkill / setHeroPassiveSkill`
- 队伍站位替换规则：`setSlotHero()`（已上阵英雄会与目标槽位交换）

## 5. 注意事项

- 页面层优先用 `useMapSystem()` 读取数据，不要在页面里维护并行状态副本。
- 页面层优先用 `useEquipmentInventory()` 读取装备数据，不要在 `HeroPage`/`InventoryPage` 各自维护独立背包。
- 页面层优先用 `useBattleSetup()` 读取编队/技能配置，不要在 `TeamPage`/`HeroPage` 维护独立战斗副本状态。
- `setRegions` 内部已经串联了结算和日志更新，避免在外部额外补写日志导致重复。
- `getRegionById` / `findNodeById` 都有兜底逻辑；如果后续改成严格模式，需同步更新页面的空态处理。
