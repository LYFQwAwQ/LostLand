# 配置文件修改指南

本文件只回答两个问题：

1. 某个可调参数现在在哪个文件里。
2. 改完以后会影响哪条链路。

如果新增了新的可调参数，必须把入口补到本文件。

## 1. 总原则

1. 能放配置文件的，优先不要硬编码在页面里。
2. 先确认参数属于“世界 / 英雄 / 战斗 / 背包 / 组织 / 任务”哪一类。
3. 改配置时要同时确认读取它的 `data` / `lib` / `page` 文件。
4. 如果一个参数只存在于 `lib` 常量里，说明它还不是正式配置项，改动时要在开发记录里说明影响面。

## 3. 世界地图配置

### 3.1 大陆 / 疆域 / 地区层级

文件：`src/config/world/worldHierarchy.json`

这里可以改：

- 大陆列表 `continents`
- 疆域列表 `dominions`
- 地区列表 `regions`
- 地区邻接关系 `neighbors`
- 地区选择弹窗坐标 `pickerPosition`

关键字段影响：

- `dominions[].regionIds`
  - 决定疆域包含哪些地区
- `regions[].neighbors`
  - 决定邻接地区切换与疆域内部连通图
- `regions[].seed`
  - 改地区随机种子，会直接改变拓扑生成结果
- `dominions[].baseRegionScale` / `scaleRange`
  - 控制地区节点规模
- `dominions[].complexityBase` / `complexitySwing`
  - 控制拓扑复杂度
- `dominions[].factionWeights`
  - 控制初始势力分布权重
- `dominions[].initialStrongFieldCount`
  - 控制初始强场节点数
- `dominions[].initEvolutionMonthCap`
  - 控制地区预演化月数上限
- `dominions[].pathWeightRange`
  - 控制边权范围

读取入口：`src/data/worldMapData.ts`

### 3.2 世界地图 UI 开放策略

当前“只开放中央大陆”的策略不在 JSON，在：

- `src/pages/WorldMapPage.tsx`

如果要恢复全部大陆开放，需要同时改：

1. 大陆按钮禁用逻辑
2. `selection` 归一化逻辑
3. 联调各大陆未完成内容

## 6. 布告栏任务配置

### 6.1 全局读取与兜底

文件：`src/data/config/bulletinMissionConfig.ts`

作用：

- 读取每个疆域的 JSON 配置
- 做字段兜底和 sanitize
- 未配置疆域回退到 `default.json`
- 提供全局“可同时接取任务上限”读取接口 `getBulletinMissionAcceptedLimit()`

### 6.2 各疆域 JSON

目录：`src/data/config/bulletinMissions/`

当前已有：

- `default.json`
- `holy-heartland.json`
- `iron-frontier.json`

主要可调项：

- 任务数量
- 收集任务的目标种类数与不同稀有度需求区间
- 讨伐任务的目标种类数与击杀区间
- 奖励材料数量区间
- 奖励消耗品数量区间
- 允许奖励的稀有度池
- 赏金 / 声望基准值、每分数成长、保底、浮动范围

实际生成逻辑：`src/lib/bulletinMissionSystem.ts`

### 6.3 可同时接取任务上限

文件：`src/data/config/bulletinMissionConfig.ts`

当前参数：

- `BULLETIN_MISSION_ACCEPTANCE_CONFIG.baseAcceptedLimit`
  - 默认值：`4`
  - 作用：限制玩家同时处于“进行中 / 可提交”状态的任务总数

读取与生效位置：

- `src/state/MapSystemProvider.tsx`
  - 在 `acceptBulletinMission()` 中做强校验
  - 对外提供 `acceptedMissionLimit` / `acceptedMissionCount` 给 UI 展示
- `src/pages/NodeActionPage.tsx`
  - 布告栏展示已接取任务数并在上限时禁用“领取委派”
- `src/pages/OrganizationPage.tsx`
  - 任务大厅界面展示全局已接取任务列表和上限计数

### 7.4 传奇装备与传奇装备技能

文件：

- `src/data/config/legendaryEquipments.json`
- `src/data/config/legendaryEquipmentSkills.json`

这里可以改：

- 传奇装备 id / 名称 / 称号 / 描述
- 固定装备位 `slot` 与固定子类型 `subtype`
- 固定等级 / 品阶 / 品质（`level` `rank` `quality`）
- 固定基础属性 `t1Stats[]`（`key` + `value`）
- 固定词条 `affixes[]`（`key` + `value`）
- 传奇装备绑定的被动技能 `passiveSkillId`
- 被动技能 id / 名称 / 描述文案

当前规则（代码约束）：

- 传奇装备通过普通装备槽位穿戴，与普通装备共用穿戴链路
- 传奇装备的等级 / 品阶 / 品质 / 基础属性 / 词条都为固定值，不会随机变化
- 品质显示上，传奇装备统一展示为“传说”，普通装备品质“legendary”档显示为“圣铸”
- 传奇装备固定 5 个符文槽（展示用途）
- 每个英雄最多可同时装备 2 件传奇装备
- 同一传奇装备全局唯一，不可重复装备给多个英雄

读取入口：

- `src/data/legendaryEquipments.ts`
- `src/state/EquipmentInventoryProvider.tsx`
- `src/pages/InventoryPage.tsx`
