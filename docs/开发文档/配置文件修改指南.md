## 2. 参数词典：`src/lib/archetypes.ts`

位置：`ARCHETYPE_PROFILES`

- `initialStrength`
  - 含义：该类型节点的基础强度底盘。
  - 调大：该类型更容易“压住局势”。
  - 调小：该类型更容易被对抗、被转化。
- `orderScale`
  - 含义：节点向外输出秩序场的系数（稳定倾向）。
  - 调大：更容易提升稳定、抑制混乱。
  - 调小：稳定扩散能力下降。
- `expansionScale`
  - 含义：节点向外输出扩张场的系数（混乱倾向）。
  - 调大：更容易扩张、侵蚀周边。
  - 调小：混乱传播放缓。
- `aggressionScale`
  - 含义：扩张进攻系数，影响扩张贡献和成长压力。
  - 调大：扩张推进更强、更快。
  - 调小：扩张冲击更弱。
- `stableTier` / `chaosTier`
  - 含义：层级标记（主要用于逻辑分类）。
  - 建议：策划一般不改。
- `defaultDifficulty`
  - 含义：UI 展示难度文案。
  - 建议：只影响显示，不直接改变结算强度。

## 3. 参数词典：`src/lib/monthlySimulation.ts`

## 3.1 全局对抗系数

- `ORDER_SAME_FACTOR = 1.2`
  - 含义：同阵营秩序加成倍率。
  - 调大：同阵营抱团稳定更明显。
- `ORDER_DIFF_FACTOR = 0.7`
  - 含义：异阵营秩序作用倍率。
  - 调大：跨阵营秩序影响更强。
- `EXPANSION_DIFF_FACTOR = 1.5`
  - 含义：异阵营扩张倍率。
  - 调大：跨阵营扩张更凶。
- `EXPANSION_SAME_FACTOR = 0.7`
  - 含义：同阵营扩张倍率。
  - 调大：同阵营内部扩张干扰增强。

## 3.2 关键触发阈值（节奏核心）

- `developmentMonths >= 4`
  - 含义：未激活点连续正向发展多少月后可开发。
  - 调大：新点诞生更慢。
  - 调小：新点诞生更快。
- `positiveMonths >= 2`（幽灵位重建）
  - 调大：幽灵位回归更慢。
  - 调小：幽灵位回归更快。
- `NOD negativeMonths >= 2`（资源点坍塌）
  - 调大：资源点更耐打。
  - 调小：资源点更脆弱。
- `ST1 negativeMonths >= 6`（主城混沌化）
  - 调大：主城更难失守。
  - 调小：主城更易失守。
- `ST2/ST3 negativeMonths >= 2`（稳定节点降级/转化）
  - 调大：稳定链更稳。
  - 调小：稳定链更易崩。
- `BL1 negativeMonths >= 2`（灾厄扩散）
  - 调大：灾厄扩散变慢。
  - 调小：灾厄扩散变快。
- `BL3/BL2 negativeMonths >= 3`（混沌升级）
  - 调大：混沌升级慢。
  - 调小：混沌升级快。
- `highProsperityMonths >= 2/4/8`
  - 含义：繁荣连续月触发升级或净化。
  - 调大：净化和正向升级更慢。
  - 调小：净化和正向升级更快。

## 3.3 其他常用调节点

- `penalty = (totalOrder + totalExpansion) * 0.1`
  - 含义：高对抗时的繁荣惩罚/补偿系数。
  - 调大：高强度对抗带来的波动更大。
- `prosperity clamp(-1800, initialStrength * 20)`
  - 含义：繁荣上下限。
  - 调大上限：高强度节点能积累更高繁荣。

## 4. 参数词典：`src/config/world/worldHierarchy.json`

位置：`continents / dominions / regions`

- `continents[].dominionIds`
  - 含义：大陆包含的疆域列表。
  - 用途：控制“点击大陆后”的疆域选择弹窗内容。
- `dominions[].regionIds`
  - 含义：疆域包含的地区列表。
  - 用途：控制地区选择弹窗内容和顺序。
- `regions[].neighbors`
  - 含义：地区邻接关系（可快捷切换目标）。
  - 用途：控制地图页“邻接地区快捷切换”按钮。
- `regions[].pickerPosition`（可选，`[x, y]`）
  - 含义：地区在“地区选择弹窗拓扑图”中的坐标（0-100）。
  - 用途：手动微调弹窗中的地区布局；未配置时按数量自动布局。
- `regions[].seed`
  - 含义：地区随机种子（同 seed 可复现同地区初图）。
  - 改动：地区拓扑、初始节点分布会变化。
- `dominions[].baseRegionScale`
  - 含义：地区基础规模（用于推导节点总数）。
  - 调大：节点更密、地区更复杂。
  - 调小：节点更少、结构更清晰。
- `dominions[].scaleRange`
  - 含义：规模扰动区间（按地区随机缩放）。
  - 调大区间跨度：同疆域下地区差异更明显。
- `dominions[].complexityBase`
  - 含义：连线复杂度基线。
  - 调大：主干更少、路线更狭窄。
  - 调小：支路更多、可达性更高。
- `dominions[].complexitySwing`
  - 含义：复杂度随机扰动幅度。
  - 调大：同疆域地区之间复杂度差异更大。
- `dominions[].pathWeightRange`
  - 含义：边权重缩放区间（影响最短路径代价）。
  - 调大上限：地形“绕行成本”更高。
- `dominions[].maxRadius`
  - 含义：场传播最大半径。
  - 调大：远距离相互影响增强，局势变化更快。
  - 调小：本地化更强，局势变化更慢。
- `dominions[].factionWeights`
  - 含义：势力权重（主权势力由权重最高者决定）。
  - 调整后：初始强场锚点归属倾向改变。
- `dominions[].weightSwing`
  - 含义：势力权重偏差（地区级随机摆动）。
  - 调大：同疆域地区势力分布更不稳定。
- `dominions[].initialStrongFieldCount`
  - 含义：初始强场锚点数量（K1）。
  - 调大：开局强势据点更多。
- `dominions[].fullFactionChance`
  - 含义：完整势力概率（未覆盖势力是否补 Hub）。
  - 调大：更容易出现多势力同时在场。
- `dominions[].initEvolutionMonthCap`
  - 含义：初始化预生长月上限。
  - 调大：地区初始状态更“有历史感”，不是纯净开局。

## 5. 参数词典：`src/data/nodeModules.ts`

## 5.1 静态池参数

- 商店/市场条目：
  - `price`：基础价格
  - `stock`：基础库存
  - `weight`：展示权重字段（当前主要用于显示）
- 酒馆条目：
  - `signingCost`：招募费用
- 铁匠条目：
  - `goldCost`：打造金币消耗

## 5.2 动态系数（最常调）

- 商店价格：`item.price * (1 + index * 0.04)`
  - `0.04` 调大：后排商品更贵。
- 市场价格：`item.price * (1 + (index % 3) * 0.03)`
  - `0.03` 调大：材料价差更大。
- 市场库存：`item.stock + (positiveMonths > 0 ? 8 : 0) - index * 3`
  - `8` 调大：繁荣后供给提升更多。
  - `3` 调大：后排库存衰减更快。
- 酒馆费用：`signingCost * (1 + max(prosperity, 0) / 3000)`
  - `3000` 调小：繁荣对招募涨价更敏感。
- 打造费用：`goldCost * (1 + index * 0.08)`
  - `0.08` 调大：高位配方涨价更明显。

## 6. 推荐改数值流程（避免改乱）

1. 一次只改一个目标（例如“只减缓混沌扩张”）。
2. 一次只改 1-3 个参数。
3. 连续结算 5-10 个月观察结果。
4. 记录“改了什么 -> 结果如何”，再进下一轮。

## 7. 快速验证清单

1. 地图可正常打开。
2. “结算下一个游戏月”可连续点击且不报错。
3. 月事件和节点变化符合你的调参目标。
4. 经济页（商店/市场/酒馆/铁匠）价格或库存变化符合预期。

## 9. 参数词典：装备系统（新增）

### 9.1 `src/lib/equipmentSystem.ts`

- `EQUIPMENT_RANK_PERCENT_RANGES`
  - 含义：品阶增幅区间（劣质/精良/卓越/完美）。
  - 调大：同品阶下的属性上限更高。
  - 调小：同品阶下的属性波动更保守。
- `EQUIPMENT_QUALITY_AFFIX_COUNT`
  - 含义：品质与词条条数的映射关系（白0到红5）。
  - 调大：高品质装备词条数量更激进。
  - 调小：装备上限下降、词条密度降低。
- `SOCKET_UNLOCK_LEVEL_STEP`
  - 含义：每多少级解锁一个插槽（当前 `20`）。
  - 调大：插槽成长更慢。
  - 调小：插槽成长更快。
- `DEFAULT_EQUIPMENT_ENVIRONMENT`
  - 含义：环境权重修正默认值（当前全部 `1`，即 `M=1.0`）。
  - 用途：后续可用于地图压制或活动对 Rank/Quality 掉率做动态修正。

### 9.2 `src/data/equipmentTemplates.ts`

- `baseWeight`
  - 含义：模板在掉落池中的抽取权重。
  - 调大：该装备模板更容易出现。
- `t1Stats[].lvl1Base / growthRate`
  - 含义：基础属性 1 级底值与每级线性成长。
  - 调大：该属性“地板”更高。
- `rankWeights`
  - 含义：该模板生成不同品阶的概率权重。
  - 调大某档：更容易出现该品阶。
- `qualityWeights`
  - 含义：该模板生成不同品质（词条数）的概率权重。
  - 调大高品质：高词条数装备出现更多。
- `affixPool[].min / max / weight`
  - 含义：词条数值范围与词条出现权重。
  - 调大 `weight`：该词条更常见。
  - 提高 `min/max`：该词条强度整体上移。
- `t1Stats[].key / affixPool[].key`
  - 约束：当前仅允许使用《设定/属性》文档中的属性键，不新增自定义键。
  - 允许键：`hp`、`mp`、`str`、`int`、`agi`、`def`、`penetration`、`critRate`、`critDamage`、`evasion`、`aggro`、`lifeSteal`、`thorns`、`elementalPierce`、`allRes`、`allBoost`、`armorPiercePct`。

### 9.3 `src/lib/equipmentScoring.ts`

- `EQUIPMENT_QUALITY_SCORE`
  - 含义：背包内部分数中，各品质的基础权重。
  - 调大高品质权重：高品质装备更容易进入高色阶。
- `EQUIPMENT_RANK_SCORE`
  - 含义：背包内部分数中，各品阶的基础权重。
  - 调大高品阶权重：高品阶装备更容易获得更高视觉档位。
- `EQUIPMENT_SCORE_THRESHOLDS`
  - 含义：内部总分对应的颜色分档阈值（低/精良/稀有/史诗/传说/神话）。
  - 调小阈值：整体颜色更“偏高级”。
  - 调大阈值：整体颜色更“偏保守”。

## 10. 参数词典：战斗系统（新增）

### 10.1 `src/lib/battleEngine.ts`

- `ACTION_THRESHOLD = 10000`
  - 含义：行动条触发阈值。
  - 调大：单位行动更慢，单场战斗时长增加。
  - 调小：单位行动更频繁。
- `ACTION_SPEED_COEFFICIENT`
  - 含义：AGI 转换为行动条推进速度的系数。
  - 调大：整体战斗加速。
  - 调小：整体战斗减速。
- `DEFENSE_K`
  - 含义：防御减算区常量（`K / (K + EffectiveDEF)`）。
  - 调大：防御影响减弱，伤害更高。
  - 调小：防御影响增强。
- `MAX_ACTIONS_PER_STEP`
  - 含义：单次逻辑 Tick 最多处理的行动次数。
  - 调大：高 AGI 场景更顺滑，但日志增长更快。
  - 调小：节流更强，可能出现行动堆积。
- `LOG_LIMIT`
  - 含义：日志列表最大缓存长度。
  - 调大：保留更多历史；调小：内存与渲染压力更小。

### 10.1.1 `src/pages/BattlePage.tsx`

  - 调大：战斗结束停顿更久，更易读日志。
  - 调小：衔接更快，更接近挂机节奏。

- `basePower`
  - 含义：技能基础数值（进入乘区前的基数）。
- `scaling`
  - 含义：技能属性系数（`str/int/def/maxHp/missingHp`）。

- `targetStatus / selfStatus`
  - 含义：状态附加配置（概率、持续、强度）。

  - 含义：附加效果数组，支持 `applyStatus/actionDelta/shield/cleanse/dispel`。
  - `applyStatus`：可直接配置附加状态（含 `immune/taunted` 等）。
  - `shield`：可配置护盾强度公式与持续回合。
  - `cleanse`：净化目标负面状态（可配数量与极性）。
  - `dispel`：驱散目标正面状态（可配数量与极性）。
  - `healAlliesOnKill`：击杀后按目标最大生命比例群体治疗（可配 `ratio`）。
- `targetType: randomEnemies` + `targetCount`
  - 含义：从敌方随机选择 N 个目标。
  - 用途：实现“随机 2/3/4 目标攻击”。

### 10.3 `src/data/battleUnits.ts`

- `resolveEnemyCount()`
  - 含义：按 BL 等级决定敌方人数区间（支持 1-6 结构）。
- `levelBonusByArchetype()`
  - 含义：BL 分档附加等级。
- `suppressionLevel`
  - 含义：地图压制转化的等级补正（影响敌方强度）。
- `hpScale / statScale`
  - 含义：敌方生命与主属性成长曲线。
- `ENEMY_POOL[].stats`
  - 含义：敌方模板基础面板与倾向。
- `ENEMY_POOL[].race`
  - 含义：敌方种族字段（如 `beast/undead`），用于技能种族克制判定。
  - 建议：与掉落风味、元素标签保持一致，避免配置语义冲突。

### 10.4 `src/data/battleDrops.ts`

- `ENEMY_DROP_TABLES[enemyId].materialRolls`
  - 含义：该怪物每场掉落材料的抽取次数区间（闭区间）。
  - 调大：材料产出更高。
- `ENEMY_DROP_TABLES[enemyId].equipmentRolls`
  - 含义：该怪物每场掉落装备的抽取次数区间（闭区间）。
  - 调大：装备掉落更频繁。
- `materials[].weight / quantity`
  - 含义：材料池权重与单次掉落数量区间。
  - 调大权重：该材料更常掉；调大数量：每次掉更多。
- `equipments[].templateIds`
  - 含义：该装备掉落组可抽取的装备模板池（细粒度可按怪物区分）。
  - 调整建议：同一组内放同风格模板，保持掉落风味一致。
- `equipments[].environment.rankWeightMultipliers / qualityWeightMultipliers`
  - 含义：该怪物装备掉落的品阶/品质权重修正。
  - 调大高档位：更容易出高品阶、高品质装备。
- `equipments[].levelOffset`
  - 含义：掉落装备等级相对怪物等级的偏移。
  - 调大：装备等级更高；调小：更保守。

### 10.5 `src/data/battleElementTriggers.ts`

- `effect`
  - 含义：元素触发器效果类型（追加伤害/回蓝/推条/拉条/群疗/降最大生命）。
  - 建议：仅在已有效果类型中调整，避免引擎逻辑与配置不匹配。
- `valueSource`
  - 含义：触发数值来源（`dealtDamage`、`attackerMaxHp`、`attackerMissingHp`、`targetMaxHp`）。
  - 调整方向：决定倍率作用的基准量。
- `ratio`
  - 含义：按 `valueSource` 计算的比例系数。
  - 调大：触发收益提升；调小：触发收益下降。
- `flat`
  - 含义：固定值效果（如行动条固定 ±500）。
  - 调大：固定触发效果更强；调小：更弱。
- `logTemplate`
  - 含义：战斗日志模板（支持 `{actor}`、`{target}`、`{value}`、`{label}` 占位符）。
  - 用途：调整复盘与日志文案，不影响数值。

## 11. 参数词典：组织系统（新增）

### 11.1 `src/data/organizationData.ts`

- `ORGANIZATION_CONFIG.gridSize`
  - 含义：组织地图总边长（当前 `96`，即 `96x96` 画布）。
  - 调大：可扩展空间更大，渲染与交互成本上升。
  - 调小：可扩展空间更小，扩展上限更快触边。
- `ORGANIZATION_CONFIG.initialTerritorySize`
  - 含义：初始领地边长（当前 `40`，即初始 `40x40`）。
  - 调大：开局可建造空间更大，扩展阶段更晚开始。
  - 调小：开局可建造空间更小，需更早使用扩展。
- `ORGANIZATION_CONFIG.boardCellSize`
  - 含义：单个网格像素尺寸（当前 `40`）。
  - 调大：单格更大，可读性更好但同屏可视格数变少。
  - 调小：单格更小，同屏可视格数增加。
- `ORGANIZATION_CONFIG.expansionPatchSize`
  - 含义：组织升级后每次扩张并入的地块边长（当前 `7`，即每次尝试扩展 `7x7`）。
  - 规则：扩展块必须在现有领地外、与现有领地相邻，且不能与已有地块相交。
  - 调大：单次扩张节奏更快。
  - 调小：单次扩张节奏更慢，规划密度更高。
- `ORGANIZATION_CONFIG.minZoom / maxZoom / zoomStep`
  - 含义：组织地图缩放范围与滚轮缩放步长。
  - 调大 `maxZoom`：可放得更近；调小 `minZoom`：可看更全局。
  - 调大 `zoomStep`：每次缩放跳变更明显。
- `ORGANIZATION_CONFIG.maxRank`
  - 含义：组织评级最大等级（当前 `10`）。
  - 调大：成长阶段更长。
- `ORGANIZATION_CONFIG.rankExpBase / rankExpGrowth`
  - 含义：评级经验需求曲线基值与每级增量。
  - 调大：升级更慢；调小：升级更快。

## 12. 参数词典：英雄生成配置（新增）

### 12.1 `src/data/config/heroGeneration.json`

- `randomHeroCountPerStartup`
  - 含义：每次刷新启动后额外生成的随机英雄数量（当前为 2）。
  - 调大：开局可选英雄更多。
- `legendarySpawnChance`
  - 含义：每个随机英雄位抽到传奇英雄的概率（当前小概率）。
  - 调大：传奇英雄出现频率更高。
- `classRollWeights`
  - 含义：普通随机英雄的职业权重分布。
  - 调大某职业：该职业在随机英雄中更常出现。
- `namePools.familyNames / namePools.givenNames`
  - 含义：普通随机英雄姓名池（姓与名组合）。
  - 扩充词库：可提升随机姓名多样性。
- `titlePoolByClass`
  - 含义：各职业普通随机英雄称号池。
  - 调整后会影响英雄页和队伍页展示文案。
- `imagePoolByClass`
  - 含义：各职业随机立绘池（URL）。
  - 调整后会影响英雄列表与战斗头像风格。
- `statProfileByClass.base / variance`
  - 含义：普通随机英雄属性底值与波动区间（`hp/mp/str/int/agi/def`）。
  - 调大 `base`：该职业总体强度上移。
  - 调大 `variance`：同职业个体差异更大。
- `standardLoadoutPools`
  - 含义：普通随机英雄初始天赋/主动/被动抽取池与抽取数量。
  - `activePickCountRange/passivePickCountRange` 控制“初始已学技能数量随机区间”（并作为初始已装数量）。
  - 仍兼容 `activePickCount/passivePickCount` 固定数量写法（未配置区间时按固定值处理）。
  - `fixedGuaranteedActiveSkillId`：固定保底主动技能 ID（按职业独立配置，且固定占用 1 个主动槽位）。
  - `totalCountWeightDecay`：数量加权衰减系数（`0~1`）；越小越偏向“总技能数更少”的组合，`1` 近似等概率。
  - 兼容：仍可使用 `alwaysIncludeActiveSkillIds`（会取首个有效技能作为保底主动）。
  - 当前默认值：每个职业普通随机英雄初始 `1` 天赋 + `4~6` 主动 + `1~2` 被动，且“主动+被动总数越大概率越低”。
  - 当前规则：技能配置界面仅能从该英雄“已学技能列表”中选择，未学技能不显示。

### 12.2 `src/data/config/legendaryHeroes.json`

- `heroes[].id/name/title/heroClass/image`
  - 含义：传奇英雄基础信息。
- `heroes[].stats`
  - 含义：传奇英雄固定属性（不走普通随机波动）。
- `heroes[].loadout.talentId/activeSkillIds/passiveSkillIds`
  - 含义：传奇英雄固定初始天赋与技能组合。

### 12.3 `src/data/config/legendaryHeroSkills.json`

- `talents[]`
  - 含义：传奇专属天赋定义（含稀有度、职业限制、说明和修饰器）。
  - 约束：仅放传奇专属，不与职业 `talents.json` 混写。
- `activeSkills[]`
  - 含义：传奇专属主动技能定义。

- `passiveSkills[]`
  - 含义：传奇专属被动技能定义。
  - 备注：静态属性加成走 `modifiers`；复杂触发机制由引擎按技能 ID 或通用机制实现。
