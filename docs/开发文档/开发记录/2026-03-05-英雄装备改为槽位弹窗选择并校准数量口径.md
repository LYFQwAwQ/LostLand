# 2026-03-05-英雄装备改为槽位弹窗选择并校准数量口径

## 1. 任务信息

- 日期：2026-03-05
- 开发者：Codex
- 任务名称：英雄装备改为槽位弹窗选择并校准数量口径
- 需求来源：用户反馈（槽位候选数量与背包不一致，且希望改为弹窗选择）

## 2. 改动目标

- 本次要解决什么问题：
  - 将英雄装备选择方式从“页面下方列表”改为“点击槽位弹窗选择”。
  - 统一数量口径：弹窗显示该槽位类型在全局背包中的总数与可装备数。
  - 保持同一装备跨英雄唯一，同时允许同英雄内槽位间移动装备。
- 不在本次范围内的内容：
  - 不新增装备合成、分解、锁定等背包操作。
  - 不改动装备数值生成规则。

## 3. 代码改动清单

- 改动文件：
  - `src/pages/HeroPage.tsx`
  - `src/state/EquipmentInventoryProvider.tsx`
  - `src/styles.css`
- 每个文件改了什么（1-2 句）：
  - `HeroPage.tsx`：移除下方候选面板，改为槽位点击后弹出装备选择窗口；窗口中展示总数/可装备数和占用状态说明。
  - `EquipmentInventoryProvider.tsx`：调整穿戴写入逻辑，支持同英雄内从旧槽位移动到新槽位；跨英雄仍禁止重复穿戴。
  - `styles.css`：新增英雄装备弹窗样式与装备可选/禁用/已装备态样式。

## 4. 影响范围

- 影响页面/模块：
  - 英雄页 `装备体系` 交互层。
  - 全局装备状态 Provider 的穿戴写入规则。
- 是否影响数值平衡：
  - 否（仅交互与状态流转调整）。
- 是否影响旧功能：
  - 保留全局唯一穿戴规则；展示形式从下方面板改为弹窗。

## 5. 验证记录

- 手动验证路径：
  - 英雄页点击任意装备槽位，确认弹窗出现并显示数量统计。
  - 在弹窗中选择可用装备后，槽位正确更新且弹窗关闭。
  - 若装备已被其他英雄穿戴，弹窗中对应项置灰不可选。
  - 若装备已在当前英雄其他槽位，点击可移动到当前槽位。
- 验证结果：
  - 构建通过：`npm run build`
  - 单测通过：`node --experimental-strip-types --test --test-isolation=none tests/equipmentSystem.test.ts`（7/7）
- 未覆盖风险：
  - 仍未覆盖移动端长列表弹窗的性能压测（当前为 64 件样本，表现正常）。
