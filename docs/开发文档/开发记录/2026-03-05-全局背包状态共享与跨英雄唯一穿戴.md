# 2026-03-05-全局背包状态共享与跨英雄唯一穿戴

## 1. 任务信息

- 日期：2026-03-05
- 开发者：Codex
- 任务名称：全局背包状态共享与跨英雄唯一穿戴
- 需求来源：用户追加需求（实现全局共享背包与已穿戴来源标记）

## 2. 改动目标

- 本次要解决什么问题：
  - 英雄页和背包页改为共享同一份背包与穿戴状态。
  - 同一件装备禁止被多个英雄同时穿戴。
  - 在背包页展示“已装备：英雄名”来源标记。
- 不在本次范围内的内容：
  - 不接入本地持久化/服务端同步。
  - 不改动掉落或经济模块。

## 3. 代码改动清单

- 改动文件：
  - `src/state/EquipmentInventoryProvider.tsx`（新增）
  - `src/main.tsx`
  - `src/pages/HeroPage.tsx`
  - `src/pages/InventoryPage.tsx`
  - `src/styles.css`
- 每个文件改了什么（1-2 句）：
  - `EquipmentInventoryProvider.tsx`：新增全局装备状态容器，统一管理背包样本、穿戴映射、归属查询与唯一穿戴规则。
  - `main.tsx`：将 `EquipmentInventoryProvider` 挂到应用根部，供路由内页面共享状态。
  - `HeroPage.tsx`：改为读取全局背包/穿戴并执行全局穿戴写入，不再维护页面本地背包副本。
  - `InventoryPage.tsx`：改为读取全局背包，并在卡片与详情中显示装备归属英雄标记。
  - `styles.css`：新增归属标记样式（卡片徽标、详情元信息）。

## 4. 影响范围

- 影响页面/模块：
  - 英雄页 `装备体系`、背包页 `装备` 标签。
  - 新增状态模块 `src/state/EquipmentInventoryProvider.tsx`。
- 是否影响数值平衡：
  - 否（仅状态管理与展示层变更）。
- 是否影响旧功能：
  - 不影响地图、节点、月结算链路。
  - 英雄页和背包页的数据已从“各自生成”改为“全局共享”。

## 5. 验证记录

- 手动验证路径：
  - 在英雄页给 A 英雄某槽位穿戴装备后，进入背包页查看该装备是否出现“已装备：A英雄”。
  - 切换到 B 英雄同类型槽位，确认该装备不再出现在候选列表（无法重复穿戴）。
  - 点击“刷新样本”后，确认英雄页与背包页同时更新背包样本。
- 验证结果：
  - 构建通过：`npm run build`
  - 单测通过：`node --experimental-strip-types --test --test-isolation=none tests/equipmentSystem.test.ts`（7/7）
- 未覆盖风险：
  - 全局状态仍为运行时内存态，刷新页面不会保留穿戴记录。
