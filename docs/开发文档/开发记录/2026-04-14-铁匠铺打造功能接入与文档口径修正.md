## 2. 改动目标

- 本次要解决什么问题：
  - 将铁匠铺“打造”从静态占位改为真实结算链路（校验材料与金币、扣除消耗、生成装备入包）。
  - 将打造配方迁移为配置文件驱动，避免在页面/模块中硬编码配方细节。
  - 同步修正文档里“铁匠铺打造占位”的过时描述。
- 不在本次范围内的内容：
  - 酒馆招募、ST2 商铺、仪式等占位模块的功能接通。
  - 强化辅助材料的正式产出链路（仍为后续 TODO）。

## 3. 代码改动清单

- 改动文件：
  - `src/data/config/forgeCraftingRecipes.json`
  - `src/data/config/forgeCraftingConfig.ts`
  - `src/data/nodeModules.ts`
  - `src/state/EquipmentInventoryProvider.tsx`
  - `src/components/forge/ForgeCraftPanel.tsx`
  - `src/pages/NodeActionPage.tsx`
  - `src/pages/OrganizationPage.tsx`
  - `src/lib/mapRules.ts`
  - `src/data/organizationData.ts`
  - `src/styles.css`
- 每个文件改了什么（1-2 句）：
  - `forgeCraftingRecipes.json`：新增打造配方主配置（模板、品质、等级、金币、材料 ID 与数量）。
  - `forgeCraftingConfig.ts`：新增打造配方读取与 sanitize 逻辑，校验模板 ID 与材料 ID 只允许使用现有配置里的合法条目。
  - `nodeModules.ts`：改为从打造配置读取配方，并保留节点入口的配方轮换与价格浮动逻辑。
  - `EquipmentInventoryProvider.tsx`：新增 `craftEquipment()` 正式结算接口，打通扣费、扣材、容量校验与装备入包。
  - `ForgeCraftPanel.tsx`：新增打造复用面板组件，展示配方、库存校验与打造反馈。
  - `NodeActionPage.tsx`：将 forge 页“打造占位”替换为真实可操作打造面板。
  - `OrganizationPage.tsx`：组织铁匠铺弹窗新增打造面板，形成强化+打造双入口一致体验。
  - `mapRules.ts` / `organizationData.ts`：更新铁匠铺文案为“强化与打造入口”。
  - `styles.css`：补充打造材料不足状态样式。
