# 开发记录

## 1. 任务信息

- 日期：2026-03-11
- 开发者：Codex
- 任务名称：布告栏任务闭环与材料上交
- 需求来源：用户提出“任务系统先落地收集类与讨伐类，且地区内可完成；收集任务需上交材料”

## 2. 改动目标

- 本次要解决什么问题：
  - 将布告栏从静态占位改为可领取、可推进、可提交的闭环任务系统。
  - 实现两类任务：收集类（上交材料）与讨伐类（击败敌人计数）。
  - 确保任务目标来自当前地区可讨伐敌人与可掉落材料，避免生成死任务。
- 不在本次范围内的内容：
  - 任务奖励中的赏金/声望未接入独立经济与声望系统（当前仅展示与结算提示）。
  - 任务刷新策略仍为地区首次生成后固定池，不含月刷新/补位机制。

  - `src/lib/bulletinMissionSystem.ts`：新增地区任务生成器与可完成性校验，封装任务状态流转规则。

  - `src/pages/NodeActionPage.tsx`：布告栏改为真实交互，收集任务按背包数量显示进度并在提交时扣材料；目标文案改为动态拼接并补兜底，避免空描述。
  - `src/pages/BattlePage.tsx`：战斗结束后将敌人击杀计数回写任务进度（保留原掉落入包逻辑）。
  - `src/styles.css`：补充按钮 `:disabled` 灰态样式，任务接取后“领取委派”按钮视觉置灰。
  - `src/data/nodeModules.ts`：移除布告栏占位任务池，保留商店/市场/酒馆/铁匠铺数据。
  - `src/lib/mapRules.ts`：更新布告栏入口描述为正式任务入口。

## 5. 验证记录

- 手动验证路径：
  - 世界地图 -> 进入 BL 节点 -> 布告栏领取任务 -> 进入战斗 -> 结束战斗 -> 返回布告栏提交。
  - 对收集任务验证“材料不足不可提交、材料足够提交时扣除库存并发放奖励”。
  - 对讨伐任务验证“击杀数累计、达标后可提交”。
- 验证结果：
  - `npm run build` 通过（`tsc -b` + `vite build`）。
  - 编译与打包成功，无类型错误。
- 未覆盖风险：
  - 未补自动化测试（任务状态机与材料扣减回滚场景仍依赖手工回归）。
  - 极端地区若无可讨伐节点，会提示无法生成任务（符合防死任务策略，但内容体验有空窗）。
