## 2. 改动目标

- 本次要解决什么问题：
  - 将布告栏任务从“代码内全局常量”改为“按疆域配置文件驱动”。
  - 支持配置：任务数量、收集/讨伐目标区间、奖励物品池、赏金与声望的基础值和波动范围。
  - 先落地中央大陆两个疆域配置，其余疆域可用默认回退，保证测试期不阻塞。
- 不在本次范围内的内容：
  - 不接入赏金/声望到正式经济或声望系统。
  - 不恢复非中央大陆地图入口（仍保持测试收敛策略）。
  - 不实现任务月刷新/轮换策略。

## 3. 代码改动清单

- 改动文件：
  - `src/lib/bulletinMissionSystem.ts`
  - `src/data/config/bulletinMissionConfig.ts`
  - `src/data/config/bulletinMissions/default.json`
  - `src/data/config/bulletinMissions/holy-heartland.json`
  - `src/data/config/bulletinMissions/iron-frontier.json`
- 每个文件改了什么（1-2 句）：
  - `bulletinMissionSystem.ts`：任务生成与奖励计算改为按 `region.dominionId` 读取配置；收集/讨伐目标数、上交/击杀数量、奖励池、赏金/声望波动全部走配置。
  - `bulletinMissionConfig.ts`：新增配置读取与安全兜底层，负责疆域映射、默认回退、区间/稀有度池合法化。
  - `default.json`：定义未配置疆域使用的默认任务参数。
  - `holy-heartland.json`、`iron-frontier.json`：定义中央大陆两个疆域的任务参数。

## 4. 影响范围

- 影响页面/模块：
  - 布告栏任务生成逻辑（节点功能页）

- 是否影响数值平衡：
  - 是。中央大陆两个疆域将按各自 JSON 参数生成任务和奖励，不再共用一套常量。
- 是否影响旧功能：
  - 否（功能语义不变）。仍保留收集任务“提交时上交材料”、讨伐任务“击杀计数推进”的闭环。
