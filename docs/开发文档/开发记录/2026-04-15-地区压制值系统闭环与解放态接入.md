# 2026-04-15-地区压制值系统闭环与解放态接入

## 1. 任务信息

- 日期：2026-04-15
- 开发者：Codex
- 任务名称：地区压制值系统闭环与解放态接入
- 需求来源：用户提出“地区压制值=解放进度”，要求战斗/任务可推进，满值清除 BL1，并联动掉落与任务奖励。

## 2. 改动目标

- 本次要解决什么问题：
  - 将地区压制值从“主要由月结算计算的静态指标”升级为“可由玩家行为推进的解放进度”。
  - 接通战斗与任务对压制值的正向贡献，形成可持续治理闭环。
  - 满压制触发地区完全解放态，清除最高级不稳定节点（BL1）。
  - 压制值接入掉落品质门槛与任务奖励提升，强化高压制经营收益。
- 不在本次范围内的内容：
  - 新增地图结算模式（仍为“仅结算当前地区”）。
  - 任务刷新机制重做（仍沿用现有生成/领取/提交规则）。
  - 经济系统全量重平衡（仅接入与压制相关的掉落/奖励增益）。

## 3. 代码改动清单

- 改动文件：
  - `src/types/game.ts`
  - `src/state/MapSystemProvider.tsx`
  - `src/lib/battleEngine.ts`
  - `src/data/battleDrops.ts`
  - `src/pages/BattlePage.tsx`
- 每个文件改了什么（1-2 句）：
  - `src/types/game.ts`
    - 扩展 `MissionBattleOutcome`，新增 `nodeArchetype` 与 `victory`，用于战斗结果回写压制值时识别节点类型与胜负。
  - `src/state/MapSystemProvider.tsx`
    - 新增 `suppressionProgressByRegionId` 维护玩家治理增量。
    - 战斗胜利按节点类型提升压制（BL1/BL2/BL3），任务提交固定提升压制。
    - 月结算后叠加治理增量，避免玩家推进被纯模拟覆盖。
    - 压制满值（100）触发完全解放态：将活跃 BL1 转换为 BL2 并写入世界日志。
    - 布告栏任务展示与实际结算按当前压制值提升奖励（材料/消耗品数量、赏金、声望）。
  - `src/lib/battleEngine.ts`
    - 战斗掉落生成入口补传 `runtime.suppression`，让掉落模块可使用当前地区压制值。
  - `src/data/battleDrops.ts`
    - `GenerateBattleDropsParams` 增加 `suppression`。
    - `buildEnemyEnvironment` 接入压制值品质修正与硬门槛：`suppression < 80` 禁出 `legendary`，`suppression < 95` 禁出 `mythic`。
  - `src/pages/BattlePage.tsx`
    - 战斗结束回写 `reportMissionBattleOutcome` 时补传 `nodeArchetype` 与 `victory`。

## 4. 影响范围

- 影响页面/模块：
  - 世界地图（月结算后压制展示与日志）
  - 节点页（任务奖励展示随压制变化）
  - 战斗页（战斗结果回写压制、掉落品质受压制影响）
  - `MapSystemProvider`、掉落系统、任务奖励链路
- 是否影响数值平衡：
  - 是。压制值可被玩家稳定推高，且会抬升任务奖励与高品质掉落概率（并受硬门槛约束）。
- 是否影响旧功能：
  - 是。BL1 在压制满值时会被强制清除；任务奖励从固定值变为随压制动态浮动。
