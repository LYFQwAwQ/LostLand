# 目前已实现内容

## 1. 文档目的

这份文档用于回答两个问题：

1. 当前版本到底已经能玩到什么程度。
2. 哪些页面虽然已经存在，但仍然只是展示层或占位入口。

本文以当前代码真实实现为准，优先描述已经接通的页面、状态、规则、配置和回写链路，不把未来规划当成已实现内容。

## 2. 状态说明

| 状态 | 含义 |
| --- | --- |
| 已闭环 | 页面、状态、规则和结果回写都已接通，可以形成完整使用链路。 |
| 半接通 | 页面和部分状态已存在，但缺少正式产出、消耗、经济或持久化闭环。 |
| 占位 | 只有入口、静态展示或演示数据，尚未形成真实系统。 |

## 3. 当前版本主闭环

当前已经形成的主闭环有 6 条：

1. 世界地图 -> 地区选择 -> 地区拓扑生成 -> 当前地区月结算 -> 月报回放。
2. 世界地图 -> 节点页 -> 布告栏接任务 -> 战斗推进或材料上交 -> 任务奖励结算。
3. 英雄页 -> 装备穿戴 -> 面板汇总 -> 战斗适配。
4. 英雄页 -> 技能槽位配置 -> 战斗页实际施放。
5. 英雄页 / 背包页 -> 记忆穿戴 -> 全局唯一占用校验。
6. 组织页 -> 地图扩张 -> 建筑摆放 -> 任务大厅 / 基地核心入口查看。

当前世界层级已经配置为：

- 5 个大陆。
- 5 个疆域。
- 5 个地区。
- 每个大陆当前各挂 1 个疆域，每个疆域当前各挂 1 个地区。

当前配置里的大陆有：

2. 北方大陆
3. 南方大陆
4. 西方大陆
5. 东方大陆

### 7.2 当前 UI 开放策略

当前代码已经支持多大陆配置，但前端 UI 只开放中央大陆入口：

1. 世界地图页会把非中央大陆选择归一化回中央大陆。
2. 其他大陆配置存在，但在界面上仍被视为未开放入口。

### 7.3 世界地图页已实现内容

`WorldMapPage` 当前已实现：

1. 通过 URL 查询参数维护 `continent` / `dominion` / `region`。
2. 支持大陆 -> 疆域 -> 地区两级弹窗选择。
3. 地区首次进入时懒生成拓扑，并缓存到 `MapSystemProvider`。
4. 地图主画布显示节点、连线、场强色彩和节点标签。
5. 支持点击节点跳转到节点页。
6. 支持测距模式，连续点击两个节点后显示最短路径和距离。
7. 支持查看地图压制值。
8. 支持“结算当前地区下一个游戏月”。
9. 支持展示月结算结果，包括激活节点数、迷雾节点数、幽灵节点数。
10. 支持按播放帧回放本月演化过程。
11. 支持查看迷雾节点的开发进度面板。

### 7.4 地区生成已实现内容

地区拓扑当前不是手写点位，而是规则生成，已经接通：

### 8.3 占位入口里已经有的数据内容

虽然商店等系统尚未闭环，但已经有固定演示数据：

1. 商店基础池 6 个条目，会按节点轮换顺序和价格。
2. 商铺基础材料池 6 个条目，会按节点轮换顺序和库存。
3. 酒馆候选池 4 人，每个节点当前展示其中 3 人。
4. 铁匠铺当前有 3 张打造配方。
5. 商铺当前有 3 条大宗回收规则文案。

### 8.4 布告栏任务已实现内容

布告栏是当前节点模块中最完整的子系统，已经实现：

1. 地区首次加载时自动生成任务。
2. 任务只从当前地区可讨伐敌人和可掉落材料中生成，避免死任务。
3. 默认任务数为：
   - 收集任务 2 个
   - 讨伐任务 2 个
4. 全局可同时接取任务上限为 4。
5. 任务状态完整支持：
   - `available`
   - `in_progress`
   - `ready_to_submit`
   - `completed`
6. 收集任务提交时会真实扣除背包材料。
7. 讨伐任务会在战斗结束后自动累计击杀进度。
8. 提交成功后会发放材料与消耗品奖励。
9. 赏金与声望会作为奖励文案展示。
10. 任务进度既会显示在节点布告栏，也会显示在组织页任务大厅。

### 8.5 布告栏当前真实回写链路

当前任务闭环链路已经形成：

1. `ensureRegionLoaded(regionId)` 生成地区任务。
2. `acceptBulletinMission(regionId, missionId)` 负责领取。
3. 收集任务由 `consumeMaterials()` 扣料。
4. `submitBulletinMission(regionId, missionId)` 负责结算任务状态。
5. `grantMissionRewards()` 发放材料和消耗品奖励。
6. 战斗结束后 `reportMissionBattleOutcome()` 回写讨伐进度。

### 8.6 仪式页当前状态

`RitualPage` 当前已经实现：

1. 只允许 BL3 节点访问。
2. 非法访问会自动跳回节点主界面。
3. 页面中已有仪式准备卡片和风险预览卡片。
4. 当前只有“开始仪式（占位）”按钮，没有正式流程。

## 14. 当前已存在但不要误判为“完整系统”的内容

以下内容虽然已经有页面、按钮或数据，但当前不能算正式完成：

1. 商店有库存列表和按钮，但没有真实买入、卖出、回购结算。
2. 商铺有材料列表和回收规则文案，但没有真实大宗贸易逻辑。
3. 酒馆有候选人池和招募按钮，但不会把英雄加入运行时队伍。
4. 铁匠铺有强化/打造 UI 和配方展示，但不会真正生成或强化装备。
5. 仪式有入口和准备页，但没有战斗或剧情流程。
6. 组织大多数功能建筑只有入口，没有正式功能页。
7. 基地核心主线只能测试接取与标记完成，没有真实完成条件和奖励结算。
8. 组织评级当前只有模拟经验入口，没有真实经验来源。
9. 背包里的消耗品目前只是示例库存，没有战斗中使用链路。
10. 任务奖励中的赏金和声望当前只展示，不写入独立全局经济状态。
11. 战斗掉落的装备当前只展示，不写入全局装备库存。
12. 传说装备和弥亚当前带有明显测试期默认注入逻辑。

## 15. 当前最重要的实现边界

这些边界对内部沟通非常重要：

1. `heroes` 不是响应式英雄仓库，而是应用启动时生成的一次性常量。
2. 英雄的运行时真相分散在两个 Provider：
   - 编队和技能在 `BattleSetupProvider`
   - 装备、材料、消耗品、记忆在 `EquipmentInventoryProvider`
3. 世界地图和任务真相只在 `MapSystemProvider`。
4. 组织地图真相只在 `OrganizationProvider`。
5. 当前只有中央大陆真正开放入口，其他大陆不是“坏了”，而是故意未开放。
6. 当前正式可消耗和可回写的资源主要只有材料、消耗品、任务状态、记忆穿戴、装备穿戴。
7. 金币、红宝石、声望还不是正式经济状态。

## 16. 当前版本一句话总结

当前版本已经不是单纯页面原型，而是一个具备“地图进入 -> 任务接取 -> 战斗推进 -> 材料回包 -> 英雄调整 -> 组织查看”的前端原型闭环；但经济系统、英雄动态招募、商店交易、铁匠铺制造、仪式流程和组织功能建筑仍处于半接通或占位阶段。
