# 战斗技能配置文件说明-策划

本文档说明当前战斗技能配置是如何被加载、校验并进入 HeroPage / BattlePage 的。

## 1. 加载方式

入口文件：`src/data/battleSkills.ts`

加载逻辑：

1. 使用 `import.meta.glob("./battleSkills/*/*.json")` 自动收集目录下 JSON。
2. 按文件名判断内容类型：
   - 主动技能：`assault.json` `defend.json` `inspire.json` `afflict.json` `succor.json`
   - 被动技能：`passives.json`
   - 天赋：`talents.json`
   - 元信息：`meta.json`
3. 额外合并 `src/data/config/legendaryHeroSkills.json`。
4. 生成：
   - `battleActiveSkills`
   - `battlePassiveSkills`
   - `battleTalents`

## 2. 目录规则

```text
src/data/battleSkills/
  common/
    meta.json
    assault.json
    defend.json
    inspire.json
    afflict.json
    succor.json
    passives.json
    talents.json
  paladin/
  mage/
  ranger/
  priest/
  enemy-common/
  enemy-normal/
  enemy-elite/
  enemy-boss/
```

### 2.1 推荐放置原则

- 所有职业都能用的基础技能：放 `common`
- 某职业专属技能：放职业目录
- 敌方技能：放 `enemy-*`
- 某个传奇英雄独有而不适合归职业目录：放 `legendaryHeroSkills.json`

## 3. 主动技能字段

主动技能写在以下文件名里：

- `assault.json`
- `defend.json`
- `inspire.json`
- `afflict.json`
- `succor.json`

### 3.1 最小模板

```json
[
  {
    "id": "demo_skill",
    "name": "示例技能",
    "rarity": "common",
    "skillPool": "class",
    "allowedHeroClasses": ["paladin"],
    "category": "assault",
    "description": "示例说明",
    "targetType": "singleEnemy",
    "effect": "damage",
    "damageType": "physical",
    "mpCost": 10,
    "cooldown": 1,
    "baseWeight": 100,
    "basePower": 120,
    "scaling": { "str": 1.1 },
    "canCrit": true
  }
]
```

### 3.2 主要字段说明

| 字段 | 说明 |
| --- | --- |
| `id` | 技能唯一 id |
| `name` | 显示名称 |
| `rarity` | `common` `rare` `epic` `legendary` |
| `skillPool` | `common` `class` `enemy` |
| `allowedHeroClasses` | 限制可用职业 |
| `conflictSkillIds` | 不能同时配置的技能 id 列表 |
| `category` | `assault` `defend` `inspire` `afflict` `succor` |
| `description` | 展示说明（主动伤害技能建议写成“背景描述 + 实际效果”两段，属性系数用中文名） |
| `targetType` | 目标类型 |
| `targetCount` | `randomEnemies` 时的目标数量 |
| `effect` | `damage` 或 `heal` |
| `damageType` | `physical` / `magic` / `elemental` |
| `element` | 元素类型 |
| `mpCost` | 消耗 MP |
| `cooldown` | 冷却回合 |
| `baseWeight` | AI 选技能基础权重 |
| `basePower` | 基础威力 |
| `scaling` | 属性倍率 |
| `canCrit` | 是否可暴击 |
| `hitCount` | 多段次数 |
| `selfStatus` | 对自己施加状态 |
| `targetStatus` | 对目标施加状态 |
| `actionDeltaSelf` | 自身行动条变动 |
| `actionDeltaTarget` | 目标行动条变动 |
| `extraEffects` | 额外效果数组 |
| `weightTuning` | 条件权重修正 |

## 4. 被动技能字段

被动技能写在 `passives.json`。

当前约定：被动技能 `description` 使用三段文本，第一段写背景描述，第二段使用 `----------------` 作为分隔线，第三段写完整中文数值说明。

### 4.1 最小模板

```json
[
  {
    "id": "demo_passive",
    "name": "示例被动",
    "rarity": "rare",
    "skillPool": "class",
    "allowedHeroClasses": ["mage"],
    "description": "示例被动说明",
    "modifiers": {
      "flat": { "int": 40 },
      "ratio": { "maxMp": 0.12 }
    }
  }
]
```

### 4.2 `modifiers` 支持字段

- `flat`
- `ratio`
- `elementBoost`
- `elementRes`

可用 key 由 `src/data/battleSkills.ts` 中 `FLAT_KEYS` 和元素枚举决定。

当前推荐 key：

- 防御：`physicalDefense` / `magicDefense`
- 穿透：`physicalPenetration` / `magicPenetration` / `physicalPenPct` / `magicPenPct` / `elementalPierce`
- 类型增伤：`physicalDamageBoost` / `magicDamageBoost` / `elementalDamageBoost`
- 最终层：`damageBoost` / `damageReduction`

旧 key 兼容：`def`、`penetration`、`armorPenPct`、`allBoost` 会在读取时分别映射为物理防御、物理穿透、物理百分比穿透、元素伤害增加。

## 5. 天赋字段

天赋写在 `talents.json`。

当前约定：天赋 `description` 与被动一致，使用“背景描述 + 虚线分隔 + 效果正文”三段文本。

### 5.1 最小模板

```json
[
  {
    "id": "demo_talent",
    "name": "示例天赋",
    "rarity": "epic",
    "skillPool": "class",
    "allowedHeroClasses": ["ranger"],
    "description": "示例天赋说明",
    "modifiers": {
      "flat": { "agi": 35 },
      "elementBoost": { "wind": 0.18 }
    }
  }
]
```

### 5.2 天赋稀有度

天赋支持：

- `common`
- `rare`
- `epic`
- `legendary`
- `unique`

## 6. `targetType` 可用值

- `self`
- `singleEnemy`
- `allEnemies`
- `randomEnemies`
- `singleAlly`
- `allAllies`
- `lowestHpAlly`

如果使用 `randomEnemies`，可以额外提供 `targetCount`。

## 7. 状态与额外效果

### 7.1 状态 key

- `frozen`
- `stunned`
- `poisoned`
- `burning`
- `guarded`
- `weakened`
- `shielded`
- `immune`
- `taunted`

### 7.2 `selfStatus` / `targetStatus` 结构

```json
{
  "key": "poisoned",
  "chance": 0.45,
  "duration": 2,
  "potency": 18
}
```

### 7.3 `extraEffects` 支持类型

#### `applyStatus`

```json
{
  "type": "applyStatus",
  "target": "targets",
  "application": {
    "key": "burning",
    "chance": 0.5,
    "duration": 2,
    "potency": 24
  }
}
```

#### `actionDelta`

```json
{
  "type": "actionDelta",
  "target": "self",
  "delta": 1800
}
```

#### `shield`

```json
{
  "type": "shield",
  "target": "targets",
  "duration": 2,
  "basePower": 160,
  "scaling": { "int": 0.9 }
}
```

#### `cleanse`

```json
{
  "type": "cleanse",
  "target": "targets",
  "removeCount": 2,
  "polarity": "negative"
}
```

#### `dispel`

```json
{
  "type": "dispel",
  "target": "targets",
  "removeCount": 1,
  "polarity": "positive"
}
```

#### `healAlliesOnKill`

```json
{
  "type": "healAlliesOnKill",
  "ratio": 0.08
}
```

## 8. `weightTuning` 写法

用于让 AI 在特定场景更倾向使用某技能。

```json
{
  "selfHpBelow": { "threshold": 0.4, "delta": 60 },
  "allyHpBelow": { "threshold": 0.35, "delta": 45 },
  "enemyHpBelow": { "threshold": 0.25, "delta": 30 },
  "enemyCountAtLeast": { "count": 3, "delta": 50 }
}
```

## 9. `meta.json`

当前主要用于设置默认主动技能：

```json
{
  "defaultActiveSkillId": "basic_attack"
}
```

如果配置的默认技能不存在，系统会自动回退到内置保底 `basic_attack`。

## 10. 与 HeroPage / 随机英雄的关系

改技能配置后要注意三处影响：

1. `HeroPage`
   - 技能候选是否正常显示
2. `BattleSetupProvider` / `battleLoadoutRules.ts`
   - 技能是否能通过职业与冲突校验
3. `heroRoster.ts`
   - 随机英雄是否还能按职业池抽到该技能

## 11. 常见错误排查

### 11.1 技能没显示在 HeroPage 候选里

检查：

1. `allowedHeroClasses` 是否包含该职业
2. 是否放错文件（主动写到 `passives.json` 等）
3. 随机 / 固定英雄的 `learnedSkills` 是否真的包含这个 skill id
4. `skillPool` 是否错误写成 `enemy`

### 11.2 导入配置后技能被自动清空

检查：

1. 技能是否不属于该职业
2. 技能是否不在该英雄已学技能列表内
3. 是否和其他已选技能冲突
4. 是否在主动/被动槽里重复出现

### 11.3 战斗时报错或技能无效果

检查：

1. `effect`、`targetType`、`damageType`、`category` 是否拼写正确
2. `scaling` / `extraEffects` 结构是否符合当前解析器支持范围
3. 新字段是否只是写进 JSON，但 `battleSkills.ts` 还没有解析
4. 需要的运行逻辑是否还没在 `battleEngine.ts` 中实现

## 12. 新增技能的推荐流程

1. 先确定放在哪个目录。
2. 写 JSON 条目。
3. 在 HeroPage 或敌人配置里给到引用入口。
4. 运行页面验证候选是否可见。
5. 进入战斗验证实际效果。
6. 如果新增了新字段，补充本文件与 `配置文件修改指南.md`。

## 13. 描述文案规范（当前实现）

1. 所有“按属性造成伤害”的主动技能，`description` 第二段需明确写系数，且属性名使用中文。
2. 系数写法示例：`120%智力`、`50%力量 + 25%防御`，不使用 `INT/STR/AGI/DEF`。
3. 被动技能、天赋统一采用三段文本：
   - 第一段：背景描述（偏叙事）
   - 第二段：分隔线 `----------------`
   - 第三段：效果正文（把 modifiers 与特殊机制展开成完整中文效果）
4. HeroPage 悬停面板中的配置小字（如 `int +25`）继续保留，不需要写入 JSON 的 `description` 中。
