# 第一章占位功能设计方案

## 1. 目标

本文档补齐当前仍处于占位或半接通状态的功能设计，作为后续开发依据。

覆盖功能：

1. BL3 仪式
2. ST2 商铺 / 大宗贸易
3. 训练营驻训
4. 远征调度室
5. 秘法图书馆
6. 魔力增幅塔
7. 消耗品正式来源与使用
8. 传说装备正式解锁
9. 记忆数值接入

原则：

1. 第一章先做“可闭环、低复杂度、能解释清楚”的版本。
2. 所有业务真相进入既有 Provider，不在页面里存平行状态。
3. 未接通的高级功能在第一章内优先锁定，不展示占位按钮。
4. 可调参数进入 `src/data/config` 或已有 data 文件，不硬塞页面。

## 2. 第一章开放策略

第一章内建议开放：

1. ST2 商铺基础版：材料买卖 + 小批量补给。
2. 消耗品基础版：可获得、可入包、可在战斗前配置，战斗中使用可后置到 P1。
3. 训练营展示版升级为最小驻训闭环：指派空闲英雄，按月结算经验。
4. 仪式作为 BL3 终局挑战入口，但需要锁定条件，不再裸露占位按钮。

第一章内建议继续锁定：

1. 远征调度室完整派遣系统。
2. 秘法图书馆技能书生产线。
3. 复杂跨节点套利的大宗贸易。
4. 传说装备全量获取循环。

## 3. 仪式设计

### 3.1 定位

仪式是 `BL3` 节点的剧情 / Boss / 地区转折入口，不是普通战斗的重复按钮。

第一章建议定位为：

- 名称：暗渠封印仪式
- 节点：`rc-dark-drain-corridor`
- 作用：提供“最终解放”的高反馈挑战入口，成功后大幅推进地区压制，并播放章节转折反馈。
- 是否强制：强制。玩家不可通过战斗和委托把压制推到 `100`，仪式是明确的终局路径。

### 3.2 解锁条件

第一章最小条件：

1. 完成 `CH1-MQ-04` 扩建基地。
2. 第一章目标地区压制值达到 `90` 或以上。
3. `rc-dark-drain-corridor` 仍为可访问 `BL3` 节点。

未满足时：

- 节点入口可显示为锁定态。
- 文案使用正式剧情口径，例如 `封印阵列尚未稳定`。

### 3.3 准备流程

页面分为四块：

1. 仪式状态
   - 未解锁 / 可准备 / 进行中 / 已完成。
2. 消耗确认
   - 消耗金币、建筑材料、怪物材料或仪式材料。
   - 消耗校验走 `EquipmentInventoryProvider`。
3. 风险预览
   - 推荐等级、敌人类型、环境词缀、失败后果。

### 3.4 结算结果

成功：

1. 标记该仪式完成。
2. 给予材料、声望、可能的传说装备解锁。
3. 推进地区压制至100。
4. 写入世界日志。

失败：

1. 不消耗唯一性解锁状态。
2. 可消耗部分普通材料。
3. 写入世界日志。
4. 不降低主线进度。

### 3.5 状态归属

- 仪式定义：建议新增 `src/data/config/rituals/*.json` 或 `src/data/rituals.ts`。
- 仪式运行状态：放在 `MapSystemProvider`，因为它绑定地区 / 节点。
- 消耗与奖励：走 `EquipmentInventoryProvider`。
- 阵容读取：走 `BattleSetupProvider`。
- 战斗执行：复用 `BattlePage` / `battleEngine`，通过 `ritualId` 或战斗场景参数区分普通讨伐。

## 4. ST2 商铺设计

### 4.1 定位

ST2 商铺不做装备交易，专注材料、消耗品与地区供需。

第一章基础版只做：

1. 材料买入。
2. 材料卖出。
3. 消耗品买入。
4. 每月刷新库存与价格。

复杂大宗贸易后置：

1. 跨节点价差套利。
2. 订单合约。
3. 商队运输风险。
4. 声望等级批发折扣。

### 4.2 页面结构

ST2 商铺页建议分为三个页签：

1. 采购
   - 展示本节点出售的材料 / 消耗品。
   - 支持数量输入与批量购买。
2. 回收
   - 展示玩家可出售材料。
   - 显示当前回收价与持有数量。
3. 行情
   - 展示本月价格浮动。
   - 只做解释和预览，不产生业务状态。

### 4.3 价格规则

基础公式：

```text
buyPrice = round(basePrice * nodeRoleMultiplier * monthlyFloat * reputationDiscount)
sellPrice = floor(buyPrice * sellRate)
```

建议第一章参数：

- `monthlyFloat`：`0.85~1.15`
- `sellRate`：`0.45~0.65`
- 消耗品库存：小批量，避免过早破坏战斗压力。
- 怪物材料：低阶材料优先，高阶材料第一章不出现或极低库存。

### 4.4 节点差异

第一章 ST2 节点可以按定位给特色库存：

| 节点 | 定位 | 特色 |
| --- | --- | --- |
| `rc-grand-cathedral` | 圣堂补给 | 治疗消耗品、净化材料 |
| `rc-royal-order-command` | 军需调拨 | 防御材料、少量强化辅助材料 |
| `rc-sage-council` | 学术采购 | 法术材料，记忆碎片后置 |
| `rc-baptism-sanctum` | 净化补给 | 异常抗性消耗品 |
| `rc-white-stone-mine` | 建材产地 | 石材类建筑材料、矿物材料 |

### 4.5 状态归属

- 商铺定义与库存模板：建议新增 `src/data/config/markets/*.json`。
- 本月库存与价格：放在 `MapSystemProvider`，因为它绑定地区 / 节点 / 世界月份。
- 玩家金币、材料、消耗品：仍在 `EquipmentInventoryProvider`。
- 页面只做展示、数量输入、调用 Provider。

## 5. 训练营设计

### 5.1 定位

训练营解决“非上阵英雄也能成长”的问题。

第一章基础版：

1. 玩家指派空闲英雄进入训练槽。
2. 每推进 1 个世界月，驻训英雄获得经验。
3. 训练营等级决定槽位数和经验倍率。
4. 魔力增幅塔提供额外经验倍率。

### 5.2 约束

1. 已在当前编队中的英雄不能驻训，避免同一英雄同时战斗和驻训。
2. 同一英雄只能占用一个训练槽。
3. 拆除训练营时，自动清空训练槽并保留已获得经验。
4. 英雄达到等级上限后仍可驻训，但不再获得经验。

### 5.3 结算公式

```text
monthlyTrainingExp = baseExpByTrainingCampLevel * (1 + manaPylonBonusRate)
```

建议第一章：

- Lv.1 训练营：每月 `80~120` 经验。
- 每级训练营增加 `20%~30%`。
- 魔力增幅塔按建筑等级提供全局加成，但第一章可先只影响训练营，不影响战斗经验。

### 5.4 状态归属

- 训练槽状态：`OrganizationProvider`
- 英雄经验写入：`EquipmentInventoryProvider.grantTrainingHeroExp()` 或复用经验写入方法
- 世界月推进触发：由 `MapSystemProvider.advanceOneMonth()` 后通知组织结算，或由 `OrganizationProvider` 监听 `worldMonth`

## 6. 远征调度室设计

远征调度室用于派出未上阵英雄执行离线任务，解决英雄冗余和材料补给。

第一章建议继续锁定，只保留正式锁定文案。

正式流程：

1. 每月生成远征任务池。
2. 玩家选择任务并指派 1~3 名空闲英雄。
3. 任务占用若干世界月。
4. 结算时根据英雄等级、职业适配、任务难度给出成功率。
5. 成功发放材料、金币、声望、少量特殊资源。
6. 失败发放保底奖励，不死亡、不永久损失英雄。

状态归属：

- 远征任务池与进行中远征：`OrganizationProvider`
- 奖励入包：`EquipmentInventoryProvider`
- 英雄可用性：读取 `HeroRosterProvider` 与 `BattleSetupProvider`

## 7. 秘法图书馆设计

秘法图书馆承接技能书、记忆碎片和图鉴研究。

第一章建议继续锁定，不开放半成品入口。

正式能力：

1. 技能书炼成
   - 消耗金币、材料、研究点。
   - 产出职业技能书。
   - 技能书用于让英雄获得新技能。
2. 记忆研究
   - 消耗记忆碎片。
   - 解锁或升级记忆。
3. 图鉴研究
   - 根据击败敌人和材料收集进度，解锁敌人弱点、掉落提示或小额加成。

状态归属：

- 技能书和记忆碎片库存：建议归 `EquipmentInventoryProvider`，因为属于背包资源。
- 研究队列与建筑等级效果：`OrganizationProvider`
- 技能拥有关系若正式落地，需要扩展 `BattleSetupProvider` 或新增英雄技能库存状态；不要只存在 HeroPage。

## 8. 魔力增幅塔设计

魔力增幅塔是非唯一增幅建筑，适合提供全局小额收益。

第一章建议先只接入训练营经验加成：

```text
manaPylonBonusRate = sum(levelBonusByManaPylonLevel)
```

后续可扩展到：

1. 战斗经验加成。
2. 技能书研究速度。
3. 仪式成功率或仪式奖励。

状态归属：

- 建筑数量和等级：`OrganizationProvider`
- 派生加成：由 `OrganizationProvider` 统一计算，对外暴露只读 selector。

## 9. 消耗品设计

第一章基础版：

1. 来源：
   - ST2 商铺购买。
   - 布告栏任务奖励。
   - 仪式奖励。
2. 展示：
   - 背包消耗品页展示真实来源，不再显示 `示例库存`。
3. 使用：
   - P0 可先做“战斗前携带槽位”。
   - P1 接入战斗中使用，包括治疗、回蓝、复活、抗性药剂。

状态归属：

- 消耗品库存：`EquipmentInventoryProvider`
- 战斗携带槽位：若只影响战斗配置，可放 `BattleSetupProvider`
- 战斗中使用次数与冷却：`BattlePage` / `battleEngine` 运行时状态

## 10. 传说装备设计

第一章原则：

1. 不再默认拥有全部传说装备。
2. 第一章最多开放 1~2 件传说装备。
3. 传说装备来源必须有明确事件：
   - 仪式首通
   - 第一章结算
   - 特定主线奖励

状态归属：

- 传说装备定义：`src/data/config/legendaryEquipments.json`
- 被动技能定义：`src/data/config/legendaryEquipmentSkills.json`
- 已解锁传说装备：`EquipmentInventoryProvider`
- 解锁来源记录：建议随 `ownedLegendaryEquipmentIds` 增加来源字段，便于背包展示。

## 11. 记忆数值设计

第一章基础版：

1. 记忆仍按职业限制穿戴。
2. 每个记忆新增结构化数值字段。
3. 战斗面板切换到“战斗数值”时包含记忆加成。
4. 战斗引擎读取同一份加成，避免页面显示和实战不一致。

第一批只支持简单加成：

1. 固定属性：`hp/mp/str/int/agi/def`
2. 百分比属性：`critRate/critDamage/lifeSteal/allRes`
3. 条件触发后置，不放第一章基础版。

状态归属：

- 记忆定义：`src/data/heroMemories.ts`
- 记忆拥有和穿戴：`EquipmentInventoryProvider`
- 战斗结算适配：`src/lib/battleAdapters.ts`

## 12. 实现拆分建议

第一批：去占位和基础闭环

1. ST2 商铺基础买卖。
2. 仪式锁定态与正式准备页。
3. 消耗品真实来源展示。
4. 移除组织经验模拟按钮。

第二批：第一章正式功能

1. 仪式挑战与结算。
2. 训练营驻训。
3. 第一章传说装备解锁。
4. 记忆数值接入。

第三批：高级组织功能

1. 远征调度室。
2. 秘法图书馆。
3. 魔力增幅塔扩展到更多系统。

## 13. 验收标准

完成后第一章不应再出现：

1. `测试阶段`
2. `占位`
3. `TODO`
4. `示例库存`
5. `暂未接入`
6. 可点击但无真实反馈的按钮

核心流程至少需要验证：

1. ST2 商铺买入 / 卖出材料后，金币和库存正确变化。
2. 仪式未解锁时显示正式锁定态，解锁后可准备并结算。
3. 训练营按月给驻训英雄发放经验。
4. 消耗品来源不再显示示例数据。
5. 传说装备只显示已解锁或图鉴态。
