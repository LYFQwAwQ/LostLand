# 07. 战斗系统模块

## 1. 模块范围

本模块覆盖：

1. 战斗入口与战斗页
2. 我方 / 敌方战斗模板组装
3. 实时战斗引擎
4. 掉落生成
5. 战斗回放与复盘视图
6. 战斗结果对背包和任务的回写

## 2. 主调用链

`NodeActionPage`
-> `BattlePage`
-> `buildAllyTeamTemplates` / `buildEnemyTeamTemplates`
-> `createBattleRuntime`
-> `stepBattle`
-> `endBattle / finalizeBattle`
-> `collectBattleDrops`
-> `reportMissionBattleOutcome`

## 4. BattlePage 当前职责

### 4.1 进入战斗前

- 用 `nodeId` 找到当前地区和节点
- 从 `BattleSetupProvider` 拿编队和技能配置
- 从 `EquipmentInventoryProvider` 拿穿戴装备
- 通过 `battleAdapters.ts` 组装我方战斗模板
- 通过 `battleUnits.ts` 生成敌方队伍

### 4.2 战斗进行中

- 使用 `setInterval(..., 16)` 驱动 `stepBattle`
- 支持开始 / 暂停 / 强制结束 / 重置本场 / 重新侦察
- 支持 1x / 2x / 3x 倍速
- 右侧战斗日志展示优先使用“连战会话累计日志”；若累计日志暂时为空，自动回退显示当前 `runtime.logs`，避免日志区出现空白

### 4.3 连战逻辑

- 若本场胜利且我方仍有存活单位，会自动进入下一场
- 下一场会继承存活英雄的 HP / MP
- 若失败或无法继续，则打开复盘弹窗
- 连战会话重置只应由“重新侦察（`battleSeed` 变化）”或“切换节点（`nodeId` 变化）”触发；掉落入包与任务回写引发的 Provider 更新不能重置 `runtime`，否则会打断自动衔接

### 4.4 战斗结束后的回写

- 我方胜利且有掉落：`EquipmentInventoryProvider.collectBattleDrops(runtime.drops)`
- 无论胜负，都会统计：
  - 本场材料获得数
  - 敌方击杀数
- 然后调用 `MapSystemProvider.reportMissionBattleOutcome(...)` 回写地区任务进度

当前 `collectBattleDrops` 已写回：

- 材料掉落 -> 材料库存
- 装备掉落 -> 全局装备背包（可在背包页与英雄装备页直接看到）

## 5. battleAdapters 做什么

`src/lib/battleAdapters.ts` 负责把前台的英雄数据转成战斗可用模板。

### 5.1 我方模板

输入：

- `heroes`
- `formation`
- `heroLoadouts`
- `equippedByHero`
- `itemMap`

输出：`BattleUnitTemplate[]`

这里会：

1. 解析英雄字符串属性为数值
2. 汇总装备属性
3. 叠加职业基础倾向
4. 按编队槽位生成 ally 单位

### 5.2 敌方模板

- 入口：`buildEnemyTeamTemplates`
- 实际来源：`src/data/battleUnits.ts`
- 会根据 node archetype、地图压制和 `sourceNodeId` 生成敌人数量与等级
- 若该节点存在固定战斗配置（`battleConfig`），优先使用节点敌人池；否则回退到全局敌人池
- 固定地图无序节点已按层级分布参数接入：
  - `FRONTIER_COUNT_DISTRIBUTION`（BL3）
  - `CONTESTED_COUNT_DISTRIBUTION`（BL2）
  - `CORE_COUNT_DISTRIBUTION`（BL1）
- 当前敌人带 5 级稀有度（常见/精英/强敌/领主/灾厄）：
  - 稀有度越高遭遇权重越低
  - 稀有度越高基础难度倍率越高
  - 稀有度越高装备品质倾向越高（通过 `loot-quality:*` 标签参与掉落环境修正）
- 当前敌人种族：亡灵 / 野兽 / 人类 / 异兽（`aberrant`）

## 6. battleEngine 负责什么

`src/lib/battleEngine.ts` 是战斗核心。

它负责：

1. 运行时单位创建
2. 行动条推进
3. 技能权重选择
4. 目标选择
5. 伤害、治疗、暴击、闪避、护盾
6. 状态施加 / 驱散 / 净化 / 免疫
7. 元素触发
8. 日志记录
9. 掉落生成
10. 回放数据统计

如果你要改“为什么这个技能会这样放 / 这个状态怎么结算 / 这个掉落怎么出”，最终都要看这里。

## 7. 技能系统当前结构

### 7.1 配置来源

- 通用技能：`src/data/battleSkills/common/*.json`
- 职业技能：`src/data/battleSkills/paladin|mage|ranger|priest/*.json`
- 敌方技能：`src/data/battleSkills/enemy-*/*.json`
- 传奇英雄补充技能：`src/data/config/legendaryHeroSkills.json`

### 7.2 运行时装载

- `src/data/battleSkills.ts` 用 `import.meta.glob` 自动收集 JSON
- 解析成：
  - `battleActiveSkills`
  - `battlePassiveSkills`
  - `battleTalents`

### 7.3 与 HeroPage 的关系

HeroPage 候选技能、导入校验、战斗引擎运行，用的是同一份技能定义。

所以改技能配置后要同时验证：

1. HeroPage 是否还能选中
2. BattlePage 是否还能正常施放
3. 是否影响随机英雄技能池

## 8. 掉落系统当前结构

### 8.1 掉落生成

- 入口：`battleEngine.ts` 的 `generateDrops`
- 材料目录：`src/data/battleDrops.ts`
- 当前掉落结构：
  - 材料按种族池掉落（亡灵/野兽/人类/异兽）
  - 当前材料总量 54 种（亡灵14 / 野兽14 / 人类14 / 异兽12）
  - 怪物稀有度决定材料卷数、装备卷数与品质偏向权重

### 8.2 掉落入包

- 战斗页结束后调用 `collectBattleDrops`
- 材料和装备都会写入全局背包
- 测试阶段点击背包“刷新装备样本”会清空战斗掉落装备池并重刷随机样本

## 10. 当前注意事项

1. 战斗页连战会自动开始下一场，调试时要留意是不是还停留在同一场。
2. 战斗结果会真实回写任务进度和材料库存。
3. 英雄页展示属性不是战斗最终属性，战斗以 `battleAdapters.ts` 输出为准。
4. 技能 JSON 改错时，问题可能同时表现为 HeroPage 候选异常和 BattlePage 运行异常。
5. 若调整敌人稀有度或种族材料池，需要同步复核 `docs/百科/怪物图鉴.md` 与 `docs/百科/材料图鉴.md`。
