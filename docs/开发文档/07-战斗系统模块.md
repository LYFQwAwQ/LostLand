# 07. 战斗系统模块

## 1. 模块职责

- 提供正式可扩展的实时战斗模板（非演示占位）。
- 支持双方 `1-6` 人参战，采用前后排结构（前排 3 + 后排 3）。
- 支持 `1 天赋 + 10 主动 + 10 被动` 槽位结构，允许示例英雄未填满槽位。
- 支持行动条驱动、动态权重选技、状态结算、战斗日志、胜负与掉落。

## 2. 关键文件

- `src/pages/BattlePage.tsx`
  - 战斗主界面：阵型、控制条、行动队列、日志、结束战斗按钮与复盘子界面。
- `src/lib/battleEngine.ts`
  - 实时战斗核心：Tick 推进、选技、伤害公式、元素触发、状态结算、复盘记录。
- `src/data/battleElementTriggers.ts`
  - 元素触发器配置表：八系元素效果的数据驱动定义（效果类型、倍率/固定值、日志模板）。
- `src/lib/battleAdapters.ts`
  - 适配层：将英雄/装备/编队/技能槽位转换为战斗模板，生成敌方队伍模板。
- `src/data/battleDrops.ts`
  - 细粒度怪物掉落表：按敌人原型配置装备池、材料池、数量与稀有度权重。
- `src/state/BattleSetupProvider.tsx`
  - 队伍站位与技能槽位全局状态来源（战斗页直接消费）。
- `src/data/battleSkills.ts`
  - 技能配置加载与运行时校验（从 JSON 配置转为运行态定义）。
- `src/data/config/legendaryHeroSkills.json`
  - 传奇英雄专属技能与天赋独立配置（不与职业池文件混用）。
- `src/data/battleSkills/`
  - 技能分层配置目录（`common/paladin/mage/enemy-normal/enemy-elite/enemy-boss/enemy-common`）。
  - 每个目录按五类主动技能文件拆分（`assault/defend/inspire/afflict/succor`），并附带 `passives/talents`。
- `src/data/battleUnits.ts`
  - 队伍上限与前后排规则、英雄默认槽位映射、敌方模板生成。
- `src/types/battle.ts`
  - 战斗类型系统：单位、技能、状态、日志、掉落明细、复盘结构、运行时状态。

## 3. 系统链路（当前实现）

1. `NodeActionPage` 的 `battle` 入口跳转到 `/battle/:nodeId`。
2. `BattlePage` 读取当前节点信息 + 全局英雄/装备/编队/技能槽位状态。
3. `battleAdapters` 生成我方与敌方 `BattleUnitTemplate`。
4. `createBattleRuntime` 初始化运行态，点击开始后 `stepBattle` 固定 Tick 推进。
5. 战斗结束后记录胜负；胜利时按 `battleDrops` 怪物掉落表生成装备与材料。
6. 战斗结束后将击杀计数回写到布告栏任务系统；收集任务改为“提交时上交背包材料”。
7. 战斗过程中持续记录复盘数据（行动快照、伤害来源、状态变化、单位统计、掉落分类统计）。

## 4. 伤害与行动（当前实现）

- 行动条阈值：`10000`，每 Tick 按 `AGI` 推进。
- 伤害公式采用多乘区：`SkillBase * Crit * Def * Elem * Extra * Reduction`。
- 状态支持：`frozen / stunned / poisoned / burning / guarded / weakened / shielded / immune / taunted`。
- 新机制：
  - `shielded`：伤害先扣护盾值，再扣生命。
  - `immune`：持续回合内免疫所有负面状态。
  - `taunted`：单体敌对技能目标被强制指向嘲讽来源。
  - `cleanse/dispel`：技能可在配置中直接声明净化/驱散效果。
- 主动技能支持 `extraEffects` 配置（附加状态、推拉条、护盾、净化、驱散），无需改引擎代码即可扩展多数常规技能逻辑。
- 主动技能目标新增 `randomEnemies + targetCount`，可实现“随机 N 敌方目标”类技能。
- `extraEffects` 新增 `healAlliesOnKill`（击杀触发全队治疗比例），用于传奇技能的击杀连锁效果。
- 元素接口覆盖八系：`fire/water/ice/wind/life/light/undead/dark`，通过 `battleElementTriggers` 做数据驱动触发，减少引擎硬编码分支。
- 已接入传奇祭司弥亚专属机制：生命属性伤害额外穿透全抗、低血线友军触发生命治疗翻倍、受击联动被动伤害。
- 敌方原型配置已新增 `race` 字段并映射为战斗标签（如 `race:undead`），用于种族克制技能判定。
- AI 选技：基础权重 + 装备/战场修正 + 动态条件修正后加权随机。
- 战斗节奏已下调（默认 `x1` 更易观察），并限制单 Tick 可处理行动数，避免日志刷屏。
- 连战规则：战斗胜利后自动进入下一场（回合间不弹复盘），我方保留当前 `HP/MP`（不自动回复）。
- 日志规则：侧栏战斗日志按“连战会话”累积显示（从第一场开始到最后一场结束），不再只显示当前单场日志。
- 战斗主循环采用 `requestAnimationFrame` 帧驱动，行动条更新更连贯，避免 `100ms` 定时器造成的跳变感。
- 战斗页提供手动“结束战斗”按钮，可中止当前战斗并在结束态弹出复盘。
- 战斗复盘改为“整场结束后弹窗展示”，战斗进行中和连战回合间都不常驻、不弹窗。
- 掉落统计支持类型分栏（装备/材料），装备掉落支持与背包一致的关键词、品质、品阶、部位筛选和排序。

## 5. 注意事项

- 本模块是正式模板，新增技能或状态时优先改 `types + data + engine`，避免把规则写死在页面层。
- 新增/删除/修改技能优先改 `src/data/battleSkills/` 目录下的 JSON 分文件；`battleSkills.ts` 只负责校验与装载，不建议手写技能常量。
- 掉落规则统一维护在 `src/data/battleDrops.ts`，按敌人原型细粒度配置。
- 讨伐类任务进度由战斗结束时按“实际击杀敌人原型”累计；收集类任务不按掉落计数，而是提交时消耗背包材料。
- 地图压制对掉落稀有度/保底/数量的修正暂未接入（按当前需求暂缓）。
- 若后续新增战斗页面子路由或队伍编辑入口，需同步更新 `01-项目与目录总览.md`。
- `BattlePage` 中节点上下文需保持引用稳定；若每次渲染都重新构建上下文对象，会导致运行态被重置，表现为“开始战斗无效”。
