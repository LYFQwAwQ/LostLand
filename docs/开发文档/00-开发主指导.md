# 00. 开发主指导（必读）

本文件定义团队统一开发流程：每次开发前看什么、开发后必须写什么。

## 1. 开发前必做（按顺序）

1. 看 `docs/开发文档/README.md`
   - 先确认本次需求属于哪个模块。
2. 看对应模块文档
   - 地图与结算：`02-地图生成与月度结算模块.md`
   - 节点功能：`03-节点交互模块.md`
   - 英雄队伍：`04-英雄与队伍模块.md`
   - 状态数据：`05-状态管理与数据模块.md`
   - 样式布局：`06-UI与样式模块.md`
   - 战斗系统：`07-战斗系统模块.md`
   - 数值改动：`配置文件修改指南.md`
3. 看代码入口（至少 3 个文件）
   - `src/main.tsx`
   - `src/App.tsx`
   - 本次要改的模块入口文件

## 2. 开发中约束

1. 先改类型，再改逻辑，再改页面
   - 有新字段先改 `src/types/game.ts`。
2. 不在页面里写并行状态副本
   - 全局地图状态统一走 `MapSystemProvider`。
3. 一次只做一个目标
   - 不把“功能改动 + 大规模重构 + 样式大改”混在同一提交。

## 3. 开发完成后必须做的事

## 3.1 必做验证

1. 功能路径走通（至少手动点一遍主流程）。
2. 无明显报错（页面控制台、路由跳转、关键按钮）。
3. 对于数值改动：连续结算 5-10 月观察是否符合目标。

## 3.2 必写文档（必须）

每次开发完成后，至少更新下面两类文档：

1. 模块文档更新（必选）
   - 在你改动对应的模块文档里补“改了什么、影响什么、注意事项”。
2. 开发记录（必选）
   - 新建一份记录文件：`docs/开发文档/开发记录/YYYY-MM-DD-任务名.md`
   - 格式使用：`docs/开发文档/开发记录/开发记录模板.md`

## 3.3 需要时再做（条件触发）

1. 如果新增了模块文档
   - 必须更新 `docs/开发文档/README.md` 索引。
2. 如果改了数值参数含义
   - 必须更新 `docs/开发文档/配置文件修改指南.md` 参数词典。
3. 如果新增了路由或页面
   - 必须更新 `01-项目与目录总览.md` 的路由或目录说明。

## 4. 开发记录命名规范

- 文件名：`YYYY-MM-DD-任务名.md`
- 示例：`2026-02-23-地图月结算阈值调整.md`

## 5. 最低交付标准（合并前检查）

1. 代码可运行。
2. 文档已更新。
3. 他人只看文档就能知道“改动点、影响面、回滚点”。
