# 03. 节点交互模块

## 1. 模块范围

本模块负责：

1. 节点主界面
2. 节点动作开放规则
3. 各动作页内容承载
4. 布告栏任务领取 / 提交 / 奖励结算
5. BL3 仪式入口跳转

本模块不负责：

- 地图生成
- 英雄详情页逻辑
- 战斗引擎本体

## 2. 当前页面结构

| 页面 | 作用 | 状态 |
| --- | --- | --- |
| `src/pages/NodeHubPage.tsx` | 节点档案 + 动作入口总览 | 已接通 |
| `src/pages/NodeActionPage.tsx` | 节点子动作页承载 | 部分接通 |
| `src/pages/RitualPage.tsx` | BL3 仪式入口页面 | 占位 |

## 3. 动作开放规则

动作规则统一在 `src/lib/mapRules.ts`：

- `ACTION_META`：动作标题和说明
- `getNodeActions(node)`：按节点状态和 archetype 给出可访问动作
- `canAccessAction(node, action)`：页面跳转权限校验

### 3.1 archetype 与动作映射

- `ST1`：详细信息 / 商店 / 酒馆 / 铁匠铺 / 布告栏
- `ST2`：详细信息 / 商铺 / 布告栏
- `ST3`：详细信息
- `BL1`：详细信息 / 战斗
- `BL2`：详细信息 / 战斗
- `BL3`：详细信息 / 战斗 / 仪式
- `NOD`：详细信息

### 3.2 状态修正

- `inactive`：不开放动作
- `ghost`：只允许 `detail`

## 4. NodeHubPage 做什么

`src/pages/NodeHubPage.tsx` 的职责很单一：

1. 根据 `nodeId` 找到地区与节点上下文
2. 展示节点当前状态、势力、难度、环境说明
3. 根据 `getNodeActions(node)` 渲染动作入口
4. 当动作被阻止时显示 `warn=blocked`

它不是业务页，只是总入口页。

## 5. NodeActionPage 当前哪些功能是真的

### 5.1 已接通闭环

#### `detail`

- 读取节点环境、驻留加成、繁荣度、基础强度
- 纯展示

#### `battle`

- 展示战斗准备信息
- 跳转到 `/battle/:nodeId`
- BL3 额外显示仪式入口

#### `bulletin`

这是当前节点交互模块里最完整的子系统。

它会：

1. 通过 `MapSystemProvider` 读取地区任务
2. 领取任务
3. 对收集任务校验库存材料
4. 调 `EquipmentInventoryProvider.consumeMaterials` 扣材料
5. 调 `MapSystemProvider.submitBulletinMission` 提交任务
6. 调 `EquipmentInventoryProvider.grantMissionRewards` 发放材料与消耗品奖励
7. 在页面展示当前进度和反馈信息

### 5.2 仍然是占位页

#### `shop`

- 库存来自 `src/data/nodeModules.ts`
- 只有列表展示，没有正式买卖结算状态

#### `market`

- 材料库存与回收规则为静态演示数据
- 没有正式交易链路

#### `tavern`

- 招募候选人来自 `src/data/nodeModules.ts`
- 只展示，不会真正修改英雄池

#### `forge`

- 图纸与强化说明来自静态数据
- 没有正式打造 / 强化结算

#### `ritual`

- 页面存在
- 仍是占位
- 只做入口保护和基础展示

## 6. 任务系统与节点页的连接点

### 6.1 任务生成

- 入口：`MapSystemProvider.ensureRegionLoaded`
- 逻辑：`src/lib/bulletinMissionSystem.ts`
- 配置：`src/data/config/bulletinMissionConfig.ts` + `src/data/config/bulletinMissions/*.json`

### 6.2 任务推进

- 收集任务：在 NodeActionPage 提交时直接校验库存
- 讨伐任务：由战斗页结束后回写到 `MapSystemProvider.reportMissionBattleOutcome`

### 6.3 任务奖励

- 材料 / 消耗品奖励：`EquipmentInventoryProvider.grantMissionRewards`
- 赏金 / 声望：目前只作为任务奖励展示文本，没有独立经济状态落地

## 7. `nodeModules.ts` 的定位

`src/data/nodeModules.ts` 是节点占位模块的静态数据源，提供：

1. 商店库存
2. 商铺库存
3. 酒馆候选
4. 铁匠铺图纸
5. 商铺回收规则文案

这些数据目前只服务页面展示，不代表完整系统已经实现。

## 8. 常见改动定位

| 需求 | 文件 |
| --- | --- |
| 改节点入口开放规则 | `src/lib/mapRules.ts` |
| 改节点主界面文案 / 入口布局 | `src/pages/NodeHubPage.tsx` |
| 改布告栏按钮逻辑 / 提交逻辑 | `src/pages/NodeActionPage.tsx` |
| 改任务生成与提交规则 | `src/lib/bulletinMissionSystem.ts` |
| 改任务配置 | `src/data/config/bulletinMissionConfig.ts` `src/data/config/bulletinMissions/*.json` |
| 改商店 / 酒馆 / 铁匠铺占位数据 | `src/data/nodeModules.ts` |
| 改仪式页入口限制或占位展示 | `src/pages/RitualPage.tsx` |

## 9. 当前注意事项

1. 节点页所有上下文都来自 `findNodeById(nodeId)`，不要自己拼节点数据。
2. 布告栏任务是“地区级”而不是“节点级”。
3. 收集任务提交会真实扣除背包材料。
4. 战斗结束会真实回写讨伐任务进度。
5. 酒馆、商店、铁匠铺还没有正式状态系统，改它们时不要误以为已经有库存结算层。
