# 03. 节点交互模块

## 1. 模块职责

- 展示单节点信息（状态、类型、势力、难度、场强、繁荣等）。
- 根据节点类型开放不同功能入口。
- 提供节点功能页（商店、市场、酒馆、铁匠铺、布告栏、战斗准备等）。
- 为 BL 节点提供到实时战斗页的跳转入口。

## 2. 关键文件

- `src/pages/NodeHubPage.tsx`
  - 节点主界面，展示档案 + 动作入口
- `src/pages/NodeActionPage.tsx`
  - 节点功能页，按 `action` 渲染不同模块
- `src/pages/RitualPage.tsx`
  - BL3 仪式专属页
- `src/pages/BattlePage.tsx`
  - 实时战斗页面（由 battle 入口跳转）
- `src/lib/mapRules.ts`
  - 动作元数据与权限映射核心
- `src/data/nodeModules.ts`
  - 商店/市场/酒馆/铁匠铺数据池与价格/库存动态系数
- `src/lib/bulletinMissionSystem.ts`
  - 布告栏任务核心：地区可完成性校验、任务生成、进度推进规则
- `src/data/config/bulletinMissionConfig.ts`
  - 布告栏任务配置读取层（按疆域选择配置，未配置疆域回退默认配置）
- `src/data/config/bulletinMissions/*.json`
  - 布告栏任务数值配置文件（一个疆域一个文件）
- `src/state/MapSystemProvider.tsx`
  - 布告栏任务状态容器（领取/提交/战斗结果回写）

## 3. 动作权限机制

1. `mapRules.ts` 中 `archetypeActionMap` 决定某 archetype 可访问动作。
2. `getNodeActions(node)` 返回节点可见动作列表。
3. `NodeActionPage` 通过 `canAccessAction` 做二次校验，不可访问时重定向回 NodeHub 并带 `warn=blocked`。

## 4. 常见修改任务

## 4.1 新增节点动作

需要同时修改：

1. `src/types/game.ts`
   - 扩展 `NodeAction` 联合类型
2. `src/lib/mapRules.ts`
   - 扩展 `ACTION_META`
   - 把动作加入 `archetypeActionMap`
3. `src/pages/NodeActionPage.tsx`
   - 在 `validActions` 中加入新动作
   - 添加对应渲染分支

## 4.2 调整商店/市场内容

修改 `src/data/nodeModules.ts` 中对应池：

- `baseShopPool`
- `marketPool`
- `tavernPool`
- `recipePool`

以及各函数中的价格/库存动态系数。

## 4.3 调整布告栏任务生成与可完成性

优先修改 `src/lib/bulletinMissionSystem.ts`：

- 任务可完成性校验：`collectRegionMissionAvailability`
- 任务生成/奖励计算逻辑：`build*MissionDefinition`、`buildMissionReward`
- 如需调数值，优先改 `src/data/config/bulletinMissions/*.json`（不要再改代码常量）
- 任务数量：`missionCount.collect / missionCount.hunt`
- 收集任务目标种类区间：`collect.targetTypeCountRange`
- 收集任务上交数量区间：`collect.requiredByRarity`
- 讨伐任务目标种类区间：`hunt.targetTypeCountRange`
- 讨伐任务击杀数量区间：`hunt.requiredCountRange`
- 奖励池与赏金/声望：`reward.allowed*Rarities`、`reward.bounty`、`reward.reputation`

页面交互与按钮状态（领取/提交反馈）在 `src/pages/NodeActionPage.tsx`。

## 4.4 调整节点详情展示字段

修改 `src/pages/NodeHubPage.tsx` 和 `src/pages/NodeActionPage.tsx` 的 `detail` 分支即可，不需要动算法层。

## 5. 注意事项

- `ritual` 动作有独立页面，不走 `NodeActionPage` 的普通分支。
- `battle` 动作是战斗准备页入口，点击后进入 `/battle/:nodeId` 实时战斗页。
- 布告栏任务进度由战斗页结束结算后回写（当前仅回写讨伐击杀数），页面本身不维护并行进度。
- 收集类任务采用“上交材料”语义：提交时按目标数量扣除背包材料，不是“仅按掉落数判定完成”。
- `inactive` 和 `ghost` 节点入口受限，改动前先确认状态约束是否仍然成立。
- 节点页面通过 URL 的 `nodeId` 找节点，不要在页面内复制状态，统一从 `MapSystemProvider` 取最新值。
