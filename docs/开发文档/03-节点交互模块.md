# 03. 节点交互模块

## 1. 模块范围

本模块负责：

1. 节点主界面
2. 节点动作开放规则
3. 各动作页内容承载
4. 布告栏任务领取 / 提交 / 奖励结算
5. BL3 仪式入口跳转

本模块不负责：

- 地图生成
- 英雄详情页逻辑
- 战斗引擎本体

## 3. 动作开放规则

动作规则统一在 `src/lib/mapRules.ts`：

- `ACTION_META`：动作标题和说明
- `getNodeActions(node)`：按节点状态和 archetype 给出可访问动作
- `canAccessAction(node, action)`：页面跳转权限校验

### 3.1 archetype 与动作映射

- `ST1`：详细信息 / 商店 / 建材交易 / 酒馆 / 铁匠铺 / 布告栏
- `ST2`：详细信息 / 商铺 / 布告栏
- `ST3`：详细信息
- `BL1`：详细信息 / 战斗
- `BL2`：详细信息 / 战斗
- `BL3`：详细信息 / 战斗 / 仪式
- `NOD`：详细信息

### 3.2 状态修正

- `inactive`：不开放动作
- `ghost`：只允许 `detail`

## 4. NodeHubPage 做什么

`src/pages/NodeHubPage.tsx` 的职责很单一：

1. 根据 `nodeId` 找到地区与节点上下文
2. 展示节点当前状态、势力、难度、环境说明
3. 根据 `getNodeActions(node)` 渲染动作入口
4. 当动作被阻止时显示 `warn=blocked`

它不是业务页，只是总入口页。

## 6. 任务系统连接点

- 任务生成：`MapSystemProvider.ensureRegionLoaded` -> `src/lib/bulletinMissionSystem.ts`
- 任务推进：收集任务在 `NodeActionPage` 校验库存，讨伐任务由 `BattlePage` 回写
- 任务奖励：`EquipmentInventoryProvider.grantMissionRewards`
- 任务上限：`MapSystemProvider.acceptBulletinMission` + 组织任务大厅
- 第一章门禁：节点铁匠铺受章节主线锁定，酒馆签约不受锁影响

## 7. `nodeModules.ts` 的定位

`src/data/nodeModules.ts` 只保留节点页仍需静态预览的数据：商店候选、酒馆候选、铁匠铺配方展示。真正的结算分别走 `EquipmentInventoryProvider`、`HeroRosterProvider` 和 `forgeCraftingRecipes.json`。

ST2 商铺正式数据已转到 `src/data/markets.ts`，并由 `MapSystemProvider` 维护“按节点、按世界月份”的库存与价格状态。

## 8. 占位功能正式设计摘要

详细设计见 `第一章占位功能设计方案.md`。本节只记录节点模块需要遵守的边界。

### 8.1 ST2 商铺

定位：

1. ST2 商铺只负责材料、消耗品与地区供需，不做装备交易。
2. 第一章基础版只需要支持材料买入、材料卖出、消耗品买入和月度价格刷新。
3. 跨节点价差、订单合约、商队风险等复杂大宗贸易后置。

页面结构：

1. `采购`：读取节点库存，扣金币，写入材料或消耗品库存。
2. `回收`：读取玩家库存，按当前回收价卖出材料。
3. `行情`：展示本月价格浮动和节点特色，不产生业务状态。

状态归属：

1. 商铺定义和库存模板：当前在 `src/data/markets.ts`。
2. 本月库存和价格：`MapSystemProvider`，因为它绑定节点、地区与世界月份。
3. 金币、材料、消耗品：`EquipmentInventoryProvider`。
4. 页面只负责数量输入、预览和调用 Provider。

第一章节点差异：

| 节点 | 商铺定位 | 特色库存 |
| --- | --- | --- |
| `rc-grand-cathedral` | 圣堂补给 | 治疗消耗品、净化材料 |
| `rc-royal-order-command` | 军需调拨 | 防御材料、少量强化辅助材料 |
| `rc-sage-council` | 学术采购 | 法术材料，记忆碎片后置 |
| `rc-baptism-sanctum` | 净化补给 | 异常抗性消耗品 |
| `rc-white-stone-mine` | 建材产地 | 石材类建筑材料、矿物材料 |

### 8.2 BL3 仪式

定位：

1. 仪式是 `BL3` 节点的剧情 / Boss / 地区转折入口，不是普通战斗按钮。
2. 第一章建议使用 `rc-dark-drain-corridor` 的“暗渠封印仪式”作为终局挑战路径。
3. 仪式不强制替代压制推进，玩家仍可通过战斗和委托把压制推到 `100`。

解锁条件建议：

1. 完成 `CH1-MQ-04`。
2. 第一章目标地区压制达到 `80` 或以上。
3. 目标 `BL3` 节点仍可访问。

页面结构：

1. 仪式状态：未解锁 / 可准备 / 已完成。
2. 阵容确认：读取 `BattleSetupProvider` 当前编队。
3. 消耗确认：调用 `EquipmentInventoryProvider` 校验金币与材料。
4. 风险预览：展示推荐等级、敌人类型、环境词缀、成功奖励和失败后果。

结算边界：

1. 仪式状态和完成标记归 `MapSystemProvider`。
2. 奖励、消耗和传说装备解锁归 `EquipmentInventoryProvider`。
3. 战斗执行复用 `BattlePage` / `battleEngine`，通过 `ritualId` 或战斗场景参数区分普通讨伐。

### 8.3 第一章入口处理

在正式闭环完成前：

1. ST2 商铺入口已接入正式交易页，不再进入静态预览。
2. BL3 仪式入口已接入正式解锁态与准备页，不再显示占位按钮。
3. 所有玩家可见文案不得出现 `占位`、`TODO`、`暂未接入`。

## 10. 当前注意事项

1. 节点页所有上下文都来自 `findNodeById(nodeId)`。
2. 布告栏任务是地区级，不是节点级。
3. `ST1/shop`、`ST1/build_materials`、`ST1/forge` 与 `ST2/market` 都已接通；商铺真实库存按世界月份刷新。
4. 传说装备不可出售；酒馆签约结果会进入运行时英雄池。
5. 第一章目标地区 `radiant-coastline` 内实际包含 `ST2` 与 `BL3` 节点，因此商铺与仪式问题属于第一章玩家可见遗留项；排期可参考 `第一章剩余开发项.md`。
