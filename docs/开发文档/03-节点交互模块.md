# 03. 节点交互模块

## 1. 模块范围

本模块负责：

1. 节点主界面
2. 节点动作开放规则
3. 各动作页内容承载
4. 布告栏任务领取 / 提交 / 奖励结算
5. BL3 仪式入口跳转

本模块不负责：

- 地图生成
- 英雄详情页逻辑
- 战斗引擎本体

## 2. 当前页面结构

| 页面 | 作用 | 状态 |
| --- | --- | --- |
| `src/pages/NodeHubPage.tsx` | 节点档案 + 动作入口总览 | 已接通 |
| `src/pages/NodeActionPage.tsx` | 节点子动作页承载 | 部分接通 |
| `src/pages/RitualPage.tsx` | BL3 仪式入口页面 | 占位 |

## 3. 动作开放规则

动作规则统一在 `src/lib/mapRules.ts`：

- `ACTION_META`：动作标题和说明
- `getNodeActions(node)`：按节点状态和 archetype 给出可访问动作
- `canAccessAction(node, action)`：页面跳转权限校验

### 3.1 archetype 与动作映射

- `ST1`：详细信息 / 商店 / 建材交易 / 酒馆 / 铁匠铺 / 布告栏
- `ST2`：详细信息 / 商铺 / 布告栏
- `ST3`：详细信息
- `BL1`：详细信息 / 战斗
- `BL2`：详细信息 / 战斗
- `BL3`：详细信息 / 战斗 / 仪式
- `NOD`：详细信息

### 3.2 状态修正

- `inactive`：不开放动作
- `ghost`：只允许 `detail`

## 4. NodeHubPage 做什么

`src/pages/NodeHubPage.tsx` 的职责很单一：

1. 根据 `nodeId` 找到地区与节点上下文
2. 展示节点当前状态、势力、难度、环境说明
3. 根据 `getNodeActions(node)` 渲染动作入口
4. 当动作被阻止时显示 `warn=blocked`

它不是业务页，只是总入口页。

## 5. NodeActionPage 当前哪些功能是真的

### 5.1 已接通闭环

#### `detail`

- 读取节点环境、驻留加成、繁荣度、基础强度
- 纯展示

#### `battle`

- 展示战斗准备信息
- 跳转到 `/battle/:nodeId`
- BL3 额外显示仪式入口

#### `bulletin`

这是当前节点交互模块里最完整的子系统。

它会：

1. 通过 `MapSystemProvider` 读取地区任务
2. 领取任务
3. 对收集任务校验库存材料
4. 调 `EquipmentInventoryProvider.consumeMaterials` 扣材料
5. 调 `MapSystemProvider.submitBulletinMission` 提交任务
6. 调 `EquipmentInventoryProvider.grantMissionRewards` 发放材料与消耗品奖励
7. 在页面展示当前进度和反馈信息
8. 领取时受“全局可同时接取任务上限”约束（当前默认上限为 4）

#### `shop`

当前 `ST1/shop` 接入“基础装备交易”闭环：

1. 节点页生成可买入装备报价（可刷新）
2. 买入时实时扣金币并写入全局背包
3. 卖出时实时加金币并从全局背包移除
4. 卖出硬规则：
   - 已穿戴装备不可出售
   - 传说装备固定禁止出售（当前版本硬性规则）
5. 页面保留 `nodeModules.ts` 的静态表，仅作为后续材料/大宗贸易内容池预览

#### `build_materials`

当前 `ST1/build_materials` 已接通“建筑材料买入”闭环：

1. 建筑材料按“基础价 + 主城浮动百分比”生成当前单价。
2. 每个主城节点使用独立浮动配置文件（`src/data/config/buildingMaterialMarkets/*.json`）。
3. 买入时实时扣金币并写入全局材料背包（与战斗材料共用库存）。
4. 当前仅接入买入，不限制堆叠上限；卖出与库存上限规则后续补齐。

#### `forge`

铁匠铺目前是“强化 + 打造”都已接通状态：

1. 强化已接通正式结算（金币 + 材料 + 成功率 + 失败处理）
2. 打造已接通正式结算（金币 + 配方材料 + 装备入包）
3. 强化规则：普通装备最高 +10，传说装备最高 +15
4. 新增“强化辅助材料”系统：
   - 幸运护符：提升当次成功率
   - 固守符印：强化失败时保护主材料不被消耗（金币仍扣除）
5. 强化与打造面板已复用到两个入口：
   - `ST1/forge`（节点动作页）
   - 组织功能建筑 `foundry`（组织页功能弹窗）
6. 打造配方读取配置文件并在加载时做合法性校验：
   - `src/data/config/forgeCraftingRecipes.json`
   - `src/data/config/forgeCraftingConfig.ts`

### 5.2 仍然是占位页

#### `tavern`

酒馆招募已接通闭环（第一章可用）：

1. 候选池仍来自 `src/data/nodeModules.ts`
2. 点击“招募”会先扣除签约金币
3. 根据候选职业与稀有度生成英雄基础属性 / 成长 / 技能预设
4. 通过 `HeroRosterProvider.recruitHero` 写入运行时英雄池
5. 新招募英雄会立即出现在：
   - 英雄页
   - 队伍配置页
   - 战斗编队可选列表

补充：当前“同节点同候选只可签约一次”为会话内限制（切换节点后重置已签约标记）。

#### `ritual`

- 页面存在
- 仍是占位
- 只做入口保护和基础展示

## 6. 任务系统与节点页的连接点

### 6.1 任务生成

- 入口：`MapSystemProvider.ensureRegionLoaded`
- 逻辑：`src/lib/bulletinMissionSystem.ts`
- 配置：`src/data/config/bulletinMissionConfig.ts` + `src/data/config/bulletinMissions/*.json`

### 6.2 任务推进

- 收集任务：在 NodeActionPage 提交时直接校验库存
- 讨伐任务：由战斗页结束后回写到 `MapSystemProvider.reportMissionBattleOutcome`

### 6.3 任务奖励

- 材料 / 消耗品奖励：`EquipmentInventoryProvider.grantMissionRewards`
- 赏金 / 声望：同样在 `grantMissionRewards` 内结算，写入全局金币与声望状态

### 6.4 可接取上限与组织任务大厅

- 可接取上限校验在 `MapSystemProvider.acceptBulletinMission`，当前默认上限 4（可配置）。
- `NodeActionPage` 布告栏会展示“已接取任务数 / 上限”，并在上限时禁用领取按钮。
- 组织建筑“任务大厅”点击后可查看所有“进行中 / 可提交”的已接取任务（跨地区汇总）。

### 6.5 组织基地核心与固定主线任务（第一章）

- 组织建筑“基地核心”点击后提供两个子界面按钮：`基地状态` 与 `主线任务`。
- `基地状态` 当前先展示“已建造建筑总数 + 各建筑数量”。
- `主线任务` 使用固定任务线，不随机生成；已完成任务会置灰并保留在列表底部。
- 当前主线 5 步条件已接通真实进度：
  - 建材采购（节点 `build_materials` 买入）
  - 战斗胜场（战斗页胜利回写）
  - 核心升级提交（基地核心中扣费 + 提交）
  - 建筑建造数量（组织建造回写）
  - 目标地区压制值 100（地图系统同步）
- 基地核心默认已建造在组织中心，不再要求玩家手动建造核心建筑。
- 主线完成后会生成章节结算摘要（月份、建材采购、胜场、提交、建造、压制值）。

### 6.6 第一章功能门禁（节点相关）

- 节点铁匠铺（`/node/:id/forge`）在第一章完成前锁定，显示统一文案：
  - `系统受损，完成当前章节主线后恢复`
- 酒馆招募不受高级功能锁影响，第一章可直接使用。

## 7. `nodeModules.ts` 的定位

`src/data/nodeModules.ts` 是节点模块的数据入口，提供：

1. 商店库存
2. 商铺库存
3. 酒馆候选
4. 铁匠铺配方（节点页会做排序与价格浮动）
5. 商铺回收规则文案

其中商店/商铺的静态库存目前用于“内容预览”，实际基础装备买卖与建材买入已经走 `EquipmentInventoryProvider` 经济链路；铁匠铺打造主配方由 `src/data/config/forgeCraftingRecipes.json` 提供。

## 9. 当前注意事项

1. 节点页所有上下文都来自 `findNodeById(nodeId)`，不要自己拼节点数据。
2. 布告栏任务是“地区级”而不是“节点级”。
3. 收集任务提交会真实扣除背包材料。
4. 战斗结束会真实回写讨伐任务进度。
5. 铁匠铺“强化 + 打造”已接通（含辅助材料），但第一章前置门禁会锁定节点铁匠铺入口；`ST1/shop` 为装备交易，`ST1/build_materials` 为建筑材料买入，`ST2/market` 仍为静态预览。

## 2026-03-16 补充说明（当前实现口径）

- 装备交易当前只接入 `ST1/shop` 页面；建筑材料买入接入 `ST1/build_materials` 页面；`ST2/market` 暂保留静态预览，不执行真实交易结算。
- 传说装备规则固定为“可强化、不可出售”，当前版本不提供配置开关。
- 种族字段在战斗中有实际作用：敌人标签保留 `race:*`，用于技能判定（如对 `undead` 额外伤害）。
