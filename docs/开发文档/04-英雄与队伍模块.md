# 04. 英雄与队伍模块

## 1. 模块范围

本模块覆盖：

1. 英雄页四个页签：属性 / 装备 / 技能 / 记忆
2. 各职业装备槽布局
3. 技能槽位配置与导入导出
4. 记忆穿戴
5. 队伍编队
6. 队伍全量预设（编队 + 技能 + 装备 + 记忆）

## 2. 当前最重要的架构事实

### 2.1 `heroes` 是静态常量

- 来源：`src/data/mockData.ts`
- 生成逻辑：`src/data/heroRoster.ts`
- 特征：应用启动时生成一次，随后不会因为页面操作而重建

这意味着：

1. HeroPage / TeamPage / BattleSetupProvider 都直接依赖同一份模块常量。
2. “酒馆招募后增加英雄”“删除英雄”“真正的英雄仓库”都不是页面级小改动。
3. 如果需求只是调初始英雄、随机职业、传奇英雄、已学技能池，改 `heroRoster.ts` 和 `src/data/config/*`。

### 2.2 英雄相关运行时状态分散在两个 Provider

- `BattleSetupProvider`
  - 编队
  - 每个英雄的技能槽位配置
- `EquipmentInventoryProvider`
  - 装备库存
  - 穿戴关系
  - 记忆拥有与穿戴

HeroPage 只是把这两部分状态拼起来展示。

## 4. HeroPage 的真实结构

### 4.1 `stats` 页签

- 主要是英雄立绘与静态面板展示
- 核心属性来自 `hero.stats`
- 元素、战斗进阶属性仍有展示性内容，不完全等于战斗引擎最终计算值

如果你要改“战斗实际数值”，不要只改这里。

### 4.2 `gear` 页签

这是当前真正接通的装备穿戴页。

它会：

1. 根据职业读取装备槽定义 `getHeroEquipSlots(hero.heroClass)`
2. 从 `EquipmentInventoryProvider.equippedByHero` 读取已穿戴装备
3. 从全局背包 `items` 中按槽位筛可选装备
4. 调 `equipItem` / `unequipItem` 完成穿脱
5. 对圣骑士双手武器做双手占位与冲突确认
6. 展示装备带来的属性加成摘要

#### 各职业装备槽布局组件

- `PaladinGearBoard.tsx`
- `MageGearBoard.tsx`
- `RangerGearBoard.tsx`
- `PriestGearBoard.tsx`

如果只是改布局或点击区域，优先改组件；如果是改槽位规则，改 `equipmentCatalog.ts` 和 Provider。

### 4.3 `skills` 页签

这是战斗配置的真实编辑入口。

它会：

1. 读取 `BattleSetupProvider.getHeroLoadout(hero.id)`
2. 通过 `getHeroSkillOptions` 只展示当前英雄“已学技能”候选
3. 用 `normalizeHeroLoadout` 做职业限制、重复技能、冲突技能校验
4. 支持导出 JSON 文本
5. 支持导入 JSON 文本并校验落盘

#### 技能页当前约束

- 天赋槽位固定只读，不可编辑
- 主动 / 被动各 10 槽
- 同一技能不允许重复占多个槽
- 有 `conflictSkillIds` 的技能不能共存
- 技能描述展示采用分段文本（支持换行）；被动/天赋悬停时维持“背景描述 + 虚线分隔 + 效果正文 + 配置小字”阅读结构

### 4.4 `memory` 页签

- 记忆数据源：`EquipmentInventoryProvider.memoryItems`
- 穿戴关系：`equippedMemoryByHero`
- 规则：同一记忆全局唯一、职业必须匹配、必须先拥有才能装备

## 5. TeamPage 做什么

`src/pages/TeamPage.tsx` 负责两件事：

### 5.1 编队

- 6 个槽位：前排 3、后排 3
- 支持点击指定槽位分配英雄
- 支持拖拽英雄互换位置
- 真正状态在 `BattleSetupProvider.formation`

### 5.2 预设

- 本地存储 key：`lostland.team.presets.v2`
- 每个预设保存两份快照：
  - `BattleSetupSnapshot`
  - `EquipmentInventorySnapshot`
- 也就是说，预设会同时保存：
  - 编队
  - 技能槽位
  - 装备穿戴
  - 材料/消耗品/记忆库存快照

如果改预设结构，要同时兼容读取旧存档。

## 6. 技能配置与战斗的连接点

英雄页改的技能槽不会只停留在 UI。

它会经过：

`HeroPage`
-> `BattleSetupProvider`
-> `BattlePage`
-> `battleAdapters.ts`
-> `battleEngine.ts`

因此改技能候选、技能冲突或默认配置时，必须同时考虑战斗页是否还能正常组装战斗模板。

## 8. 当前注意事项

1. `heroes` 不是响应式英雄池。
2. HeroPage 的属性展示不等于战斗最终结算值，战斗实际值还要叠加装备、技能、被动、元素加成。
3. 预设会覆盖装备与库存快照，调试时注意不要误以为只保存编队。
4. 记忆库存和装备库存都在同一个 Provider，不要另起状态。
