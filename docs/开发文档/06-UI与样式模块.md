# 06. UI 与样式模块

## 1. 当前样式结构

项目没有使用 CSS Modules、Tailwind 或分文件 SCSS，样式集中在：

- `src/styles.css`

布局入口在：

- `src/components/layout/MainLayout.tsx`

## 2. MainLayout 负责什么

`MainLayout` 只负责全局框架：

1. 左侧日志面板
2. 左侧资源概览
3. 左侧导航
4. 右侧主内容 `Outlet`

如果改的是整个应用骨架、导航位置、日志/资源概览区，优先看这里。

## 4. 当前 UI 实现特点

### 4.1 统一视觉变量

`styles.css` 顶部定义了全局变量：

- `--bg`
- `--panel`
- `--card`
- `--line`
- `--text`
- `--muted`
- `--gold`

改全局主题优先改变量，不要直接全文件替换颜色。

### 4.2 大部分页面用 class，少量场景用内联样式

当前内联样式主要用于“必须动态计算坐标或尺寸”的场景，例如：

1. 世界地图节点标签偏移
2. 世界地图场强高亮
3. 英雄技能 hover 浮层定位
4. （历史）组织地图缩放与平移
5. 进度条宽度

这些场景保留内联样式是合理的，不要为了统一形式强行改回纯 class。

### 4.3 页面样式和业务逻辑还耦合在同一个页面文件里

这是当前代码现实。改某页样式时一般需要同时看：

- 页面 JSX 结构
- `styles.css` 对应前缀区块

## 5. 改样式时的推荐方式

### 5.1 正确做法

1. 先在页面里确认已有 class 命名
2. 到 `styles.css` 搜同名前缀
3. 在原有分区下继续补样式
4. 保持同一模块的命名连续

### 5.2 不推荐做法

1. 在 JSX 里大量追加匿名内联样式
2. 新增与语义无关的临时 class
3. 为单一页面问题改全局基础元素样式
4. 把已有模块前缀打散成无规律命名

## 7. 当前注意事项

1. 样式都在一个文件里，提交前一定要确认没有误伤其他模块前缀。
2. 页面 class 名已经比较固定，优先复用，不要轻易重命名整段。
3. 动态定位和缩放类场景先看页面代码，不要只盯 `styles.css`。

## 8. 响应式断点与防挤压约定（2026-05-25）

针对“部分分辨率下按钮/卡片挤压”的问题，样式层新增了统一处理策略：

1. 全局骨架改为弹性列宽。
   - `.app-shell` 使用 `minmax(248px, 300px) minmax(0, 1fr)`，避免主内容区被硬挤压。
   - `.main-panel` 增加 `min-width: 0`，允许网格子项正确收缩。
2. 页面内双栏布局统一允许收缩并在中等分辨率提前降级。
   - `team / inventory / battle / map-info` 在 `@media (max-width: 1380px)` 下切为单列。
   - 对应容器子项统一补 `min-width: 0`，减少文本与按钮堆叠变形。
3. 交互控件行支持换行。
   - `inventory-tabs`、`organization-functional-tabs` 增加 `flex-wrap: wrap`。
4. 全局壳层在 `@media (max-width: 1180px)` 提前折叠为单列，降低侧栏对内容区的横向挤压。
