# 第一章剩余开发项

## 1. 文档目的

- 本文档用于收敛“第一章当前仍会让玩家明显感觉到测试态 / 占位态 / 半接通态”的剩余问题。

## 2. 统计范围

- 章节范围：第一章目标地区 `radiant-coastline`（圣启海岸）。
- 判定标准：
  - 第一章玩家可直接进入或在主导航中直接看到；
  - 页面文案明确带有 `测试`、`占位`、`TODO`、`示例库存`、`暂未接入` 等字样；
  - 或者入口虽然开放，但实际仍是静态展示 / 假按钮 / 半闭环。

## 2.1 设计落点

占位功能的正式设计已经收敛到以下文档：

1. 总方案：`第一章占位功能设计方案.md`
2. 仪式 / ST2 商铺：`03-节点交互模块.md`
3. 消耗品 / 传说装备 / 记忆：`04-英雄与队伍模块.md`
4. 状态归属与规划配置入口：`05-状态管理与数据模块.md`
5. 训练营 / 远征调度室 / 秘法图书馆 / 魔力增幅塔：`../百科/建筑百科.md`

## 3. P0：优先清理的玩家可见问题

- 当前表现：
  - `BL3` 节点可进入仪式页；
  - 主按钮直接显示 `开始仪式（占位）`。
- 涉及文件：
  - `src/pages/RitualPage.tsx`
  - `src/lib/mapRules.ts`
  - `src/data/fixedRegionTopologies.ts`
- 修复建议：
  - 若第一章不需要仪式：直接隐藏入口，或统一纳入章节锁定态；
  - 若第一章必须保留仪式：补齐正式闭环，包括阵容确认、消耗校验、进入战斗或事件、结算回写；
  - 在未完成前，不应保留可点击但没有真实结果的主操作按钮。

  - P1 方案：把 `market` 补成正式原材料 / 大宗贸易闭环，再重新开放；

## 6. 建议开发顺序

1. 先清理所有玩家直接可见的 `测试` / `占位` / `TODO` / `示例库存` 字样。
2. 再处理假入口和假交互：
   - 仪式页
   - ST2 商铺
   - 训练营槽位
3. 然后回收测试期资源逻辑：
   - 默认全传说
   - 示例消耗品库存
   - 组织页调试按钮
4. 最后补正式系统缺口：
   - 商铺正式贸易
   - 仪式正式流程
   - 训练营正式驻训
   - 记忆数值接入
   - 传说装备缺失被动配置

## 7. 推荐拆分方式

为避免一次改动过大，建议拆成以下几个独立任务：

1. 第一章前台测试文案清理
   - 只处理玩家可见文案、假按钮、调试入口。
2. 第一章节点遗留功能收尾
   - 仪式、ST2 商铺、节点说明口径统一。
3. 第一章背包与英雄展示收尾
   - 传说装备持有规则、消耗品来源、记忆说明收口。
4. 第一章组织基地收尾
   - 训练营、建筑说明、锁定文案与高级功能展示规则。
